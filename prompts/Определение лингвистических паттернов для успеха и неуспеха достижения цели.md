# Определение лингвистических паттернов для успеха и неуспеха достижения цели

## Запрос

После нахождения паттернов успеха и неуспеха зависимостей действий друг от друга, нужно будет найти ещё и лингвистические паттерны которые наиболее часто соответствуют успеху или неуспеху достижения цели.

Предположим что для этого есть корпус размеченных текстов со всеми лингвистическими сущностями и свойствами для каждого слова или словосочетания, а также все 4 уровня описания связей между ними: вопросный (как в школе), онтологический (типичные IS_A, PART_OF и так далее), синтаксические, семантические.

Если сможешь приведи примеры таких паттернов из области продления жизни и антистарения.

## Ответ

Отличный вопрос — вы фактически переходите от **поведенческих/процедурных паттернов** к **лингвистико-семантическим паттернам успеха/неуспеха**, и это очень правильный шаг для `knowledge_map_core`.

Ниже я дам:

1. **Чёткую рамку**: что именно считать «лингвистическим паттерном успеха/неуспеха»
2. **Типологию паттернов по 4 уровням связей**, которые вы перечислили
3. **Конкретные примеры из области продления жизни и антистарения**, максимально приближённые к реальным корпусным данным
4. **Как эти паттерны связывать с паттернами действий** (ключевой момент)

Я намеренно не ухожу в нейросети — всё формализуемо, объяснимо и совместимо с графом.

---

### 1. Что такое «лингвистический паттерн успеха / неуспеха»

Формально:

> **Лингвистический паттерн успеха** — это повторяющаяся конфигурация
> **лексем + грамматических ролей + семантических отношений**,
> которая статистически коррелирует с `success = true` для заданной цели.

Важно:

* Это **не просто слова**, а *структуры*.
* Один и тот же паттерн может работать для разных целей.
* Паттерн может быть **локальным** (в одном предложении) или **дискурсивным** (через несколько предложений).

---

### 2. Универсальная типология лингвистических паттернов (под ваш граф)

Я предложу удобную классификацию, которая хорошо ложится на граф + статистику.

#### A. Паттерны КАУЗАЛЬНОСТИ (самые сильные)

Связывают **действие → механизм → эффект → цель**

**Общая форма**

```
[Action] → [Biological Mechanism] → [Physiological Change] → [Longevity Outcome]
```

---

#### B. Паттерны УСЛОВНОСТИ / ОГРАНИЧЕНИЙ

Определяют **когда действие работает**, а когда — нет.

```
Action effective ONLY_IF Condition
Action fails IF Context
```

---

#### C. Паттерны МОДАЛЬНОСТИ И СТЕПЕНИ ДОКАЗАТЕЛЬНОСТИ

Очень важны для отделения «успешных» научных утверждений от спекулятивных.

```
has been shown to
is associated with
may improve
fails to significantly
```

---

#### D. Паттерны ОПЕРАЦИОНАЛИЗАЦИИ

Связывают абстрактную цель с измеримыми метриками.

```
lifespan extension measured by
increase in median lifespan
reduction in age-related mortality
```

---

### 3. Примеры лингвистических паттернов из антистарения

(по всем 4 уровням)

Я приведу **один и тот же фрагмент**, но разложу его по уровням.

---

### Пример 1 — УСПЕШНЫЙ паттерн (калорийное ограничение)

#### Текст (типичный корпусный)

> *Caloric restriction **extends lifespan** by **activating autophagy** and **reducing oxidative stress** in mammalian models.*

---

#### 3.1 Вопросный уровень (школьный)

| Вопрос         | Ответ                     |
| -------------- | ------------------------- |
| Что делает?    | extends lifespan          |
| За счёт чего?  | activating autophagy      |
| Дополнительно? | reducing oxidative stress |
| Где?           | mammalian models          |

➡ **Вопросный паттерн успеха**

```
What action → What effect → By what mechanism
```

---

#### 3.2 Онтологический уровень

```
Caloric restriction IS_A Dietary intervention
Autophagy IS_A Cellular maintenance process
Oxidative stress IS_A Aging-related mechanism
Lifespan extension IS_A Longevity outcome
```

➡ **Онтологический паттерн успеха**

```
Intervention
  └─ affects → Aging mechanism
         └─ leads_to → Longevity outcome
```

---

#### 3.3 Синтаксический уровень

```
SUBJECT: Caloric restriction
VERB: extends
OBJECT: lifespan
ADVERBIAL_CAUSE: by activating autophagy
COORDINATED_CAUSE: reducing oxidative stress
```

➡ **Синтаксический паттерн**

```
NOUN (intervention)
  + ACTIVE VERB (extends)
  + ABSTRACT NOUN (lifespan)
  + by + GERUND (mechanism)
```

Это **очень сильный паттерн успеха**.

---

#### 3.4 Семантический уровень

```
ACTION → CAUSES → MECHANISM
MECHANISM → REDUCES → DAMAGE
MECHANISM → MAINTAINS → CELLULAR FUNCTION
```

➡ **Семантический паттерн**

```
Positive intervention
  → activates maintenance
  → reduces damage
```

---

### Пример 2 — НЕУСПЕШНЫЙ паттерн (антиоксидантные добавки)

#### Текст

> *High-dose antioxidant supplementation **fails to extend lifespan** and **may interfere with beneficial stress responses**.*

---

#### Вопросный уровень

```
Что делает? → fails to extend lifespan
Почему? → interferes with beneficial stress responses
```

---

#### Онтологический

```
Antioxidant supplementation IS_A Intervention
Beneficial stress responses IS_A Adaptive mechanism
```

➡ **Онтологический паттерн неуспеха**

```
Intervention
  └─ inhibits → Adaptive mechanism
         └─ prevents → Longevity benefit
```

---

#### Синтаксический

```
SUBJECT: supplementation
VERB: fails to extend
OBJECT: lifespan
MODAL_VERB: may interfere
```

➡ **Ключевой синтаксический маркер неуспеха**

```
fails to + VERB
may interfere with
```

---

#### Семантический

```
ACTION → NEGATES → POSITIVE ADAPTATION
```

---

### Пример 3 — Условный успех (senolytics)

#### Текст

> *Senolytic treatment **improves healthspan** **when administered intermittently**, but **causes toxicity under continuous exposure**.*

---

#### Это **золотой паттерн**, потому что он даёт условия.

**Семантический шаблон**

```
Action → Success IF Condition_A
Action → Failure IF Condition_B
```

Такой паттерн особенно ценен для планирования.

---

### 4. Типичные лингвистические маркеры успеха (из корпуса)

#### Глаголы успеха

```
extends
improves
enhances
promotes
restores
maintains
delays
attenuates age-related
```

#### Глаголы неуспеха

```
fails to
does not significantly
exacerbates
accelerates aging
induces toxicity
disrupts homeostasis
```

---

### 5. Как связать лингвистические паттерны с паттернами действий

Ключевая идея:

> **Лингвистический паттерн = объяснение / обоснование паттерна действий**

Пример:

#### Паттерн действий

```
[reduce_calories] → [activate_autophagy] → [reduce_damage] → [lifespan_extension]
```

#### Соответствующий лингвистический паттерн

```
ACTION extends lifespan by activating MECHANISM
```

➡ В `knowledge_map_core` это должно быть **одно и то же знание**, выраженное:

* процедурно (действия),
* лингвистически (текст),
* онтологически (граф).

---

### 6. Как такие паттерны извлекать автоматически (кратко)

1. Группировать тексты по `success / failure`.
2. Извлекать:

   * dependency subtrees,
   * predicate–argument structures,
   * causal markers (`by`, `through`, `via`, `results in`).
3. Считать:

   * `P(pattern | success)` vs `P(pattern | failure)`
   * lift, odds ratio.
4. Сохранять паттерны как **шаблоны**, а не строки.

---

### 7. Ключевой философский момент (очень важно)

> **В успешных анти-эйджинг паттернах почти всегда есть механизм.**
> **В неуспешных — либо его нет, либо он подавляет адаптацию.**

Это фундаментально:

* *Activate maintenance* → успех
* *Suppress stress/adaptation* → провал

## Запрос

Покажи алгоритм связывания лингвистических паттернов с action-patterns.

## Ответ

Отлично. Ниже — **алгоритм связывания лингвистических паттернов с action-patterns**, именно в том виде, в котором его можно положить в `knowledge_map_core`: формально, объяснимо, без обязательных нейросетей, с чёткими шагами, структурами данных и псевдокодом.

Я сначала дам **концептуальную схему**, затем **формальную модель**, потом **пошаговый алгоритм**, и в конце — **пример на антистарении** и **псевдокод**, максимально близкий к реальной реализации.

---

### 0. Ключевая идея (в одном абзаце)

> **Лингвистический паттерн и action-pattern — это две проекции одного и того же знания.**
> Action-pattern описывает *что делается* (процедура),
> лингвистический паттерн — *почему и как это работает* (механизм, условия, модальность).
> Связывание — это не строковое соответствие, а **сопоставление ролей, причинности и эффектов**.

---

### 1. Базовые сущности (минимальный набор)

#### 1.1 Action-pattern

```
AP = {
  actions: [a1, a2, ..., ak],
  success_rate,
  conditions,
  effects
}
```

Пример:

```
[a_reduce_calories,
 a_activate_autophagy,
 a_reduce_cell_damage]
→ lifespan_extension
```

---

#### 1.2 Linguistic-pattern

```
LP = {
  predicates,
  arguments,
  relations,
  modality,
  polarity
}
```

Пример:

```
"Caloric restriction extends lifespan by activating autophagy"
```

---

#### 1.3 Общая семантическая форма (ядро)

Оба паттерна приводятся к **канонической форме**:

```
Event(Action)
  └─ CAUSES → Mechanism
         └─ LEADS_TO → Outcome
```

Это **ключ** для связывания.

---

### 2. Канонизация (самый важный шаг)

#### 2.1 Канонизация action-pattern

Action-pattern переводится в **семантический граф эффектов**:

```
a1 → produces → state1
state1 → enables → a2
a2 → reduces → damage
damage → negatively_affects → lifespan
```

Результат:

```
AP_sem = {
  ACTION: a_reduce_calories,
  MECHANISM: autophagy_activation,
  EFFECT: damage_reduction,
  OUTCOME: lifespan_extension
}
```

---

#### 2.2 Канонизация linguistic-pattern

Из текста извлекается:

* предикат
* аргументы
* причинные маркеры
* направленность (polarity)

Пример:

```
extends(lifespan)
by(activating(autophagy))
```

Каноническая форма:

```
LP_sem = {
  ACTION: caloric_restriction,
  MECHANISM: autophagy_activation,
  EFFECT: damage_reduction?,   (implicit)
  OUTCOME: lifespan_extension
}
```

---

### 3. Общая структура связывания

Связывание — это **графовое сопоставление**:

```
match(AP_sem, LP_sem) → score ∈ [0,1]
```

где совпадения идут по:

* ролям (ACTION, MECHANISM, EFFECT, OUTCOME)
* типам отношений
* полярности (успех / неуспех)
* условиям (IF / WHEN)

---

### 4. Алгоритм (по шагам)

---

#### Шаг 1. Извлечение лингвистических паттернов

Из корпуса (размеченного):

Для каждого предложения:

1. dependency parsing
2. semantic role labeling
3. извлечение подграфов с:

   * глаголами действия
   * causal markers (`by`, `via`, `through`, `results in`)
   * результатами (`extends lifespan`, `improves healthspan`)

Результат:

```
LP_list = [LP1, LP2, ...]
```

---

#### Шаг 2. Извлечение action-patterns

Из логов/графа действий:

* частые последовательности
* условные цепочки
* цепочки с высоким lift

Результат:

```
AP_list = [AP1, AP2, ...]
```

---

#### Шаг 3. Канонизация обоих типов

Для каждого AP и LP строим **семантические шаблоны**:

```
AP_sem_list
LP_sem_list
```

---

#### Шаг 4. Матчинг ролей (core matching)

Для каждой пары `(AP_sem, LP_sem)`:

| Роль      | Совпадение                   |
| --------- | ---------------------------- |
| ACTION    | exact / ontology / embedding |
| MECHANISM | exact / IS_A                 |
| EFFECT    | optional                     |
| OUTCOME   | exact                        |
| POLARITY  | must match                   |
| MODALITY  | compatible                   |

---

#### Шаг 5. Скоринг соответствия

Пример функции:

```
score =
  wA * match(ACTION)
+ wM * match(MECHANISM)
+ wE * match(EFFECT)
+ wO * match(OUTCOME)
+ wP * polarity_match
+ wC * condition_match
```

Где `match(x)` ∈ [0,1].

---

#### Шаг 6. Фильтрация и связывание

Если `score ≥ θ`, создаём связь:

```
(AP) -[EXPLAINED_BY {score, support}]-> (LP)
```

---

### 5. Псевдокод (практический)

```python
def link_linguistic_to_action_patterns(AP_sem_list, LP_sem_list, ontology):
    links = []
    for ap in AP_sem_list:
        for lp in LP_sem_list:
            score = 0.0

            score += 0.25 * ontology.match(ap["ACTION"], lp["ACTION"])
            score += 0.30 * ontology.match(ap["MECHANISM"], lp["MECHANISM"])
            score += 0.20 * ontology.match(ap.get("EFFECT"), lp.get("EFFECT"))
            score += 0.20 * ontology.match(ap["OUTCOME"], lp["OUTCOME"])

            if ap["POLARITY"] != lp["POLARITY"]:
                continue
            score += 0.05

            if score >= 0.7:
                links.append({
                    "action_pattern": ap["id"],
                    "linguistic_pattern": lp["id"],
                    "score": score
                })
    return links
```

#### Linguistic-pattern

```
"Fasting promotes longevity by enhancing autophagic clearance of senescent cells"

```

```

```

Совпадение:

```
MECHANISM: suppression_of_adaptation

```

### 7. Что это даёт системе

1. **Объяснимость**
   Action-pattern получает текстовое/семантическое объяснение *почему он работает*.

2. **Обратное планирование**
   Можно идти от цели → механизм → действия, используя текст как подсказку.

3. **Генерация новых действий**
   Если есть LP без AP → можно синтезировать новые action-patterns.

4. **Фильтрация ложных цепочек**
   Action-pattern без лингвистической поддержки → низкий приоритет.

---

### 8. Ключевой принцип (запомнить)

> **Action-pattern без механизма — подозрителен.**
> **Лингвистический паттерн без действий — гипотеза.**
> Их связывание превращает гипотезы в планы, а планы — в объяснимое знание.

# Запрос

Напиши алгоритм генерации новых action-patterns из LP.

# Ответ

Ниже — **строгий, реализуемый алгоритм генерации новых `action-patterns` из лингвистических паттернов (LP)**, именно под вашу архитектуру `knowledge_map_core`, с учётом того, что:

* действия ↔ цели взаимозаменяемы,
* между высокоуровневыми действиями и целью могут отсутствовать низкоуровневые шаги,
* мы хотим **генерировать новое**, а не просто пересобирать старое,
* алгоритм должен работать **без нейросетей** (но я укажу, где их можно подключить опционально).

Я дам:

1. **Концептуальную модель**
2. **Формальные структуры**
3. **Пошаговый алгоритм**
4. **Псевдокод**
5. **Пример из антистарения**
6. **Критерии фильтрации мусора (очень важно)**

---

### 1. Ключевая идея

> **Лингвистический паттерн содержит скрытый план действий, но в свернутом виде.**
> Генерация action-pattern — это **разворачивание лингвистического каузального шаблона**
> в **исполняемую последовательность действий**, согласованную с уже известными паттернами.

Проще:

```
LP = "Action X improves Outcome Y by Mechanism Z"
↓
AP = [do X] → [activate Z] → [measure Y]
```

---

### 2. Формальная модель

#### 2.1 Вход: Linguistic Pattern (LP)

```python
LP = {
  "id": "lp_42",
  "ACTION": "caloric_restriction",
  "MECHANISM": "autophagy_activation",
  "EFFECT": "cellular_cleanup",
  "OUTCOME": "lifespan_extension",
  "POLARITY": "positive",
  "CONDITIONS": ["intermittent", "nutrient_deprivation"],
  "MODALITY": "assertive"  # vs speculative
}
```

---

#### 2.2 Выход: Action Pattern (AP)

```python
AP = {
  "actions": ["reduce_calories", "induce_autophagy", "clear_damaged_components"],
  "expected_outcome": "lifespan_extension",
  "mechanism": "autophagy_activation",
  "conditions": ["intermittent"],
  "confidence": 0.78,
  "origin": "generated_from_lp_42"
}
```

---

### 3. Основной алгоритм (логика)

#### Шаг 0. Фильтрация LP (жёстко обязательно)

LP **НЕ используется**, если:

* `POLARITY != positive`
* `MODALITY` ∈ { speculative, hypothetical } *(если вы не хотите гипотезы)*
* отсутствует `MECHANISM` **и** `OUTCOME`

Это критично для качества.

---

#### Шаг 1. Построение каузального скелета

Из LP строится **каузальный шаблон**:

```
ACTION → MECHANISM → EFFECT → OUTCOME
```

Если `EFFECT` отсутствует — допускаем прямую связь:

```
MECHANISM → OUTCOME
```

---

#### Шаг 2. Преобразование семантических ролей в action-слоты

Для каждой роли создаётся **слот действия**:

| Роль LP   | Тип action-слота              |
| --------- | ----------------------------- |
| ACTION    | high_level_action             |
| MECHANISM | biological_process_activation |
| EFFECT    | state_change                  |
| OUTCOME   | goal / terminal_state         |

Пример:

```
caloric_restriction → high_level_action
autophagy_activation → process_activation
cellular_cleanup → state_change
```

---

#### Шаг 3. Заполнение слотов реальными действиями

##### 3.1 Источники действий

Для каждого слота ищем кандидатов:

1. **Из существующих action-patterns**
   (действия, которые уже реализуют этот механизм/эффект)

2. **Из онтологии / лексикона**
   IS_A, CAUSES, ENABLES

3. **Из лингвистических вариантов**
   (normalize: activate / induce / enhance → ACTIVATE)

---

##### 3.2 Генерация кандидатов

Для каждого слота:

```
slot_candidates[slot] = {a1, a2, a3}
```

---

#### Шаг 4. Комбинаторная сборка action-chain

Собираем **новые цепочки**, комбинируя кандидатов:

```
[a_action] × [a_mechanism] × [a_effect]
```

❗ Ограничения:

* порядок должен соответствовать каузальности,
* действия не должны конфликтовать по предусловиям,
* цепочка **не должна полностью совпадать** с уже известной.

---

#### Шаг 5. Оценка сгенерированного action-pattern

Каждому кандидату присваивается score:

```
score =
  α * LP_confidence
+ β * compatibility_with_existing_patterns
+ γ * novelty
- δ * length_penalty
```

Где:

* `compatibility` — среднее `P(success | subchain)`
* `novelty` — 1 − max_similarity_to_existing_AP

---

#### Шаг 6. Фильтрация и сохранение

Сохраняем AP, если:

* `score ≥ θ`
* все действия существуют в онтологии
* есть путь к `OUTCOME`

---

### 4. Псевдокод (реалистичный)

```python
def generate_action_patterns_from_lp(LP, action_ontology, known_action_patterns):
    if LP["POLARITY"] != "positive":
        return []

    causal_slots = [
        ("ACTION", "high_level"),
        ("MECHANISM", "process"),
        ("EFFECT", "state_change")
    ]

    slot_candidates = {}

    for role, slot_type in causal_slots:
        concept = LP.get(role)
        if not concept:
            continue
        slot_candidates[role] = action_ontology.get_actions_for(concept)

    candidates = []

    for a in slot_candidates.get("ACTION", []):
        for m in slot_candidates.get("MECHANISM", []):
            for e in slot_candidates.get("EFFECT", [None]):
                chain = [a, m]
                if e:
                    chain.append(e)

                if is_duplicate(chain, known_action_patterns):
                    continue

                score = evaluate_chain(chain, LP, known_action_patterns)
                if score > 0.7:
                    candidates.append({
                        "actions": chain,
                        "expected_outcome": LP["OUTCOME"],
                        "origin_lp": LP["id"],
                        "score": score
                    })

    return candidates
```

5. сохраняет объяснимость и расширяемость

---

## 0. Ключевая идея пайплайна (одной фразой)

> **Обратное планирование отвечает на вопрос “что нужно для цели”,
> LP отвечает “почему это вообще может работать”,
> AP отвечает “как это сделать”.**

Гипотеза = *есть «почему», но нет «как»*
План = *есть «почему» + «как» + достижимая цепочка*

---

## 1. Общая архитектура пайплайна

```
GOAL
 ↓ (backward planning)
REQUIRED MECHANISMS
 ↓
LINGUISTIC PATTERNS (LP)
 ↓
AP GENERATION (from LP)
 ↓
ACTION PATTERNS (AP)
 ↓
PLAN VALIDATION & SCORING
 ↓
FINAL PLANS
```

---

## 2. Формальные статусы знания (очень важно)

В `knowledge_map_core` **каждое знание имеет статус**:

| Статус        | Условие                       |
| ------------- | ----------------------------- |
| `FACT`        | AP есть + подтверждён успехом |
| `PLAN`        | AP есть + достижима цель      |
| `HYPOTHESIS`  | LP есть, AP нет               |
| `UNSUPPORTED` | AP есть, LP нет               |
| `REJECTED`    | противоречие механизмов       |

Это не философия — это **алгоритмическая необходимость**.

## 3. Единый пайплайн (по шагам)

---

### ШАГ 1. Вход: цель (GOAL)

Пример:

```
GOAL = "extend_lifespan"
```

Цель — это **узел**, который может быть:

* конечным состоянием,
* действием,
* подцелью для другой цели.

---

### ШАГ 2. Обратное планирование: цель → механизмы

#### 2.1 Извлекаем LP, которые **утверждают достижимость цели**

Из корпуса:

```
LP_goal = all LP where OUTCOME == GOAL and POLARITY == positive
```

Примеры:

* autophagy_activation → lifespan_extension
* senescent_cell_clearance → lifespan_extension
* metabolic_flexibility → longevity

➡️ Это **не действия**, это *необходимые механизмы*.

---

#### 2.2 Формируем требования (REQUIREMENTS)

```
REQUIREMENTS = {
  autophagy_activation,
  senescent_cell_clearance,
  mitochondrial_quality
}
```

Это ответ на вопрос:

> «Что должно быть достигнуто, чтобы цель стала возможной?»

---

### ШАГ 3. Проверка: есть ли готовые AP?

Для каждого `mechanism ∈ REQUIREMENTS`:

```
AP_found = find AP where AP.mechanism == mechanism
```

#### Возможные случаи:

| Случай       | Интерпретация      |
| ------------ | ------------------ |
| AP найден    | механизм реализуем |
| AP не найден | разрыв → гипотеза  |

---

### ШАГ 4. LP → AP генерация (заполнение разрыва)

Если **LP есть**, но **AP нет**:

```
LP(mechanism → goal)
AND
¬∃ AP(mechanism)
⇒ HYPOTHESIS
```

#### Запускается генератор AP из LP

(алгоритм из предыдущего ответа, но теперь в контексте цели)

Результат:

```
Generated_AP = {
  actions: [...],
  mechanism: M,
  expected_outcome: GOAL,
  origin: LP
}
```

---

### ШАГ 5. Валидация AP (встраивание в план)

Каждый сгенерированный AP проверяется:

#### 5.1 Каузальная достижимость

```
actions → mechanism → goal ?
```

#### 5.2 Совместимость

* нет ли антагонистических механизмов
* нет ли конфликтов предусловий

#### 5.3 Статистическая поддержка

* есть ли частичные совпадения с успешными паттернами
* LP confidence

---

### ШАГ 6. Формирование плана (PLAN)

Если AP прошёл валидацию:

```
PLAN = backward_chain(
  initial_state,
  AP.actions,
  GOAL
)
```

Теперь это **не гипотеза**, а **план**.

## 4. Как LP становятся гипотезами или планами

### Формальное правило статусов

```text
LP ∧ ¬AP  → HYPOTHESIS
LP ∧ AP ∧ reachable → PLAN
AP ∧ ¬LP → UNSUPPORTED
LP ∧ AP ∧ contradiction → REJECTED
```

## 5. Псевдокод полного пайплайна

```python
def full_planning_pipeline(goal, LPs, known_APs, ontology):
    plans = []
    hypotheses = []

    # STEP 1: find LPs supporting goal
    relevant_LPs = [lp for lp in LPs if lp["OUTCOME"] == goal and lp["POLARITY"] == "positive"]

    # STEP 2: extract required mechanisms
    mechanisms = set(lp["MECHANISM"] for lp in relevant_LPs if "MECHANISM" in lp)

    for mech in mechanisms:
        APs = [ap for ap in known_APs if ap["mechanism"] == mech]

        if APs:
            for ap in APs:
                if reachable(ap, goal):
                    plans.append(ap)
        else:
            # hypothesis
            related_LPs = [lp for lp in relevant_LPs if lp["MECHANISM"] == mech]
            generated_APs = []
            for lp in related_LPs:
                generated_APs += generate_action_patterns_from_lp(lp, ontology, known_APs)

            if generated_APs:
                for ap in generated_APs:
                    if validate(ap):
                        plans.append(ap)
            else:
                hypotheses.append({
                    "mechanism": mech,
                    "supported_by": related_LPs
                })

    return plans, hypotheses
```

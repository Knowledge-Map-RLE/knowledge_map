# Поиск лингвистических паттернов в Neo4j

## Теория

### Структура графа

Граф знаний Карты Знаний состоит из двух уровней:

```
Уровень 1: Действия (Actions)
   (Action) ───LEADS_TO──→ (Action)

Уровень 2: Лексические единицы (LexicalUnit)
   (LexicalUnit) ──PART_OF──→ (Action)
   (LexicalUnit) ──DEPENDS_ON──→ (LexicalUnit)
```

#### Узлы

| Метка | Что хранит | Ключевые свойства |
|-------|-----------|-------------------|
| `Action` | Извлечённое действие из текста | `uid`, `label_text`, `verb` (лемма), `action_class`, `norm_key`, `doc_id`, `sentence_text` |
| `LexicalUnit` | Отдельный токен (слово) | `uid`, `text` (форма), `lemma` (лемма), `pos` (NOUN/VERB/...), `pos_fine` (VBZ/NN/...), `dep` (nsubj/dobj/...), `is_stop`, `is_punct`, `doc_id` |

#### Рёбра

| Тип | Направление | Смысл | Свойства |
|-----|-------------|-------|----------|
| `LEADS_TO` | Action → Action | Причинно-следственная связь | `relation_subtype` (causes/enables/prevents), `confidence`, `status` |
| `PART_OF` | LexicalUnit → Action | Токен входит в действие | `token_index`, `doc_id` |
| `DEPENDS_ON` | LexicalUnit → LexicalUnit | Синтаксическая зависимость | `dep_label` (nsubj/dobj/amod/compound/...), `doc_id` |

### Что такое лингвистический паттерн

**Лингвистический паттерн** — это шаблон, описывающий:
1. **Узлы** с определёнными атрибутами (лемма, POS, dependency)
2. **Рёбра** с определёнными типами (зависимости, причинные связи)
3. **Путь** через граф произвольной длины (n шагов)

Пример паттерна фиксированной длины:
> «Глагол-ингибитор → dobj → существительное-мишень»
```
(verb:LexicalUnit {lemma:"inhibit"})-[:DEPENDS_ON {dep_label:"dobj"}]->(obj:LexicalUnit {pos:"NOUN"})
```

Пример паттерна неограниченной длины:
> «Цепочка причинно-следственных связей: inhibit → X → Y → Z»
```
(Action {verb:"inhibit"})-[:LEADS_TO*1..5]->(final:Action)
```

## Базовые запросы

### 1. Поиск лексических единиц по атрибутам

```cypher
// Все глаголы с леммой "inhibit"
MATCH (lu:LexicalUnit {lemma: "inhibit", pos: "VERB"})
RETURN lu.text, lu.doc_id, lu.dep
LIMIT 100
```

```cypher
// Все существительные в позиции прямого дополнения
MATCH (lu:LexicalUnit {pos: "NOUN", dep: "dobj"})
RETURN lu.lemma, count(*) AS cnt
ORDER BY cnt DESC
LIMIT 50
```

```cypher
// Все модификаторы (amod) — прилагательные при существительных
MATCH (lu:LexicalUnit {dep: "amod"})
RETURN lu.text, lu.lemma, count(*) AS cnt
ORDER BY cnt DESC
```

### 2. Поиск через действие-контейнер

```cypher
// Все действия класса "mechanism" с глаголом "activate"
MATCH (a:Action {action_class: "mechanism", verb: "activate"})
RETURN a.label_text, a.doc_id, a.sentence_text
```

```cypher
// Все Action, содержащие слово "mTOR" (через LexicalUnit)
MATCH (lu:LexicalUnit {lemma: "mtor"})-[:PART_OF]->(a:Action)
RETURN DISTINCT a.label_text, lu.text, a.doc_id
```

## Паттерны фиксированной длины

### 3. Синтаксические зависимости (2 узла)

```cypher
// Субъект глагола: (сущ)-[nsubj]->(глагол)
MATCH (subj:LexicalUnit {pos:"NOUN"})-[:DEPENDS_ON {dep_label:"nsubj"}]->(verb:LexicalUnit {pos:"VERB"})
RETURN subj.lemma, verb.lemma, count(*) AS cnt
ORDER BY cnt DESC
LIMIT 50
```

```cypher
// Прямое дополнение: (глагол)-[dobj]->(сущ)
MATCH (verb:LexicalUnit {pos:"VERB"})-[:DEPENDS_ON {dep_label:"dobj"}]->(obj:LexicalUnit {pos:"NOUN"})
RETURN verb.lemma, obj.lemma, count(*) AS cnt
ORDER BY cnt DESC
LIMIT 50
```

```cypher
// Прилагательное → существительное (amod)
MATCH (adj:LexicalUnit {pos:"ADJ"})-[:DEPENDS_ON {dep_label:"amod"}]->(noun:LexicalUnit {pos:"NOUN"})
RETURN adj.lemma, noun.lemma, count(*) AS cnt
ORDER BY cnt DESC
```

### 4. Трёхзвенные паттерны

```cypher
// Полная SVO конструкция: субъект → глагол → объект
MATCH (s:LexicalUnit {pos:"NOUN"})-[:DEPENDS_ON {dep_label:"nsubj"}]->(v:LexicalUnit {pos:"VERB"})
      -[:DEPENDS_ON {dep_label:"dobj"}]->(o:LexicalUnit {pos:"NOUN"})
RETURN s.lemma, v.lemma, o.lemma, count(*) AS cnt
ORDER BY cnt DESC
LIMIT 30
```

```cypher
// Цепочка модификаций: прил → сущ1 ← compound ← сущ2
// "cellular senescence pathways" → (cellular)-amod→(senescence)←compound-(pathways)
MATCH (adj:LexicalUnit {pos:"ADJ"})-[:DEPENDS_ON {dep_label:"amod"}]->(n1:LexicalUnit {pos:"NOUN"})
      <-[:DEPENDS_ON {dep_label:"compound"}]-(n2:LexicalUnit {pos:"NOUN"})
RETURN adj.lemma, n1.lemma, n2.lemma, count(*) AS cnt
ORDER BY cnt DESC
```

```cypher
// Пассивная конструкция: объект ← nsubj:pass ← глагол ← agent/by
MATCH (obj:LexicalUnit)-[:DEPENDS_ON {dep_label:"nsubj:pass"}]->(verb:LexicalUnit {pos:"VERB"})
RETURN obj.lemma, verb.text, verb.doc_id
LIMIT 50
```

### 5. Причинно-следственные связи между Actions

```cypher
// Что приводит к чему: Action → LEADS_TO → Action
MATCH (a1:Action)-[r:LEADS_TO {status:"confirmed"}]->(a2:Action)
RETURN a1.label_text, r.relation_subtype, a2.label_text, count(*) AS cnt
ORDER BY cnt DESC
LIMIT 30
```

```cypher
// Все следствия ингибирования mTOR
MATCH (inhib:Action {verb:"inhibit"})-[:LEADS_TO]->(result:Action)
WHERE inhib.label_text CONTAINS "mTOR"
RETURN inhib.label_text, result.label_text, result.action_class
```

## Паттерны неограниченной длины (Variable-Length Paths)

### 6. Цепочки LEADS_TO произвольной длины

Синтаксис: `-[:LEADS_TO*min..max]->`

```cypher
// Цепочка причинно-следственных связей длиной 1-5 шагов
// "Rapamycin inhibits mTOR" → ... → "extends longevity"
MATCH path = (start:Action)-[:LEADS_TO*1..5]->(end:Action)
WHERE start.verb = "inhibit"
RETURN 
    [n IN nodes(path) | n.label_text] AS chain,
    length(path) AS steps
ORDER BY steps DESC
LIMIT 20
```

```cypher
// Кратчайший путь между двумя концептами
// Как "inhibit mTOR" связано с "longevity"?
MATCH path = shortestPath(
    (start:Action {verb: "inhibit"})-[:LEADS_TO*1..10]-(end:Action)
)
WHERE end.label_text CONTAINS "longevity"
RETURN 
    [n IN nodes(path) | n.label_text] AS path,
    length(path) AS steps
```

```cypher
// Все достижимые действия из начального ингибирования
MATCH (start:Action {verb:"inhibit"})-[:LEADS_TO*1..]->(reachable:Action)
WHERE start.label_text CONTAINS "mTOR"
RETURN DISTINCT reachable.label_text, reachable.action_class
```

> ⚠️ **Важно:** `*1..` без верхнего предела может привести к экспоненциальному росту. Всегда ограничивайте `*1..N` где N = 5-10.

### 7. Синтаксические цепочки произвольной длины

```cypher
// Цепочка зависимостей от глагола: verb → obj → compound → compound → ...
MATCH path = (v:LexicalUnit {pos:"VERB", lemma:"inhibit"})
             -[:DEPENDS_ON*1..4]->(leaf:LexicalUnit)
WHERE NOT (leaf)-[:DEPENDS_ON]->()
RETURN 
    [n IN nodes(path) | n.text] AS phrase,
    [n IN nodes(path) | n.lemma] AS lemmas,
    [r IN relationships(path) | r.dep_label] AS deps
```

```cypher
// Найти все слова, зависящие от глагола (через любую цепочку зависимостей)
MATCH (v:LexicalUnit {lemma:"inhibit", pos:"VERB"})
      -[:DEPENDS_ON*1..3]->(dependent:LexicalUnit)
RETURN DISTINCT dependent.lemma, dependent.pos, dependent.dep
ORDER BY dependent.lemma
```

### 8. Смешанные паттерны (оба уровня графа)

```cypher
// Найти цепочку: Action → LEADS_TO → Action, где второй Action содержит
// существительное, связанное зависимостью с глаголом внутри
MATCH (a1:Action)-[:LEADS_TO]->(a2:Action)
      <-[:PART_OF]-(verb2:LexicalUnit {pos:"VERB"})
      -[:DEPENDS_ON {dep_label:"dobj"}]->(obj2:LexicalUnit {pos:"NOUN"})
RETURN 
    a1.label_text,
    a2.label_text,
    verb2.text,
    obj2.lemma
```

```cypher
// Сравниваем синтаксическую структуру двух действий,
// связанных причинно-следственной связью
MATCH (a1:Action)-[:LEADS_TO]->(a2:Action)
      <-[:PART_OF]-(lu1:LexicalUnit {pos:"VERB"})
      -[:DEPENDS_ON*1..2]->(dep1:LexicalUnit),
      (a2)<-[:PART_OF]-(lu2:LexicalUnit {pos:"VERB"})
      -[:DEPENDS_ON*1..2]->(dep2:LexicalUnit)
WHERE dep1.pos = "NOUN" AND dep2.pos = "NOUN"
RETURN 
    a1.label_text, dep1.lemma,
    a2.label_text, dep2.lemma
```

## Паттерны неограниченной глубины: теория и практика

### Переменная длина в Cypher

```
()-[:TYPE]->()          — ровно 1 шаг
()-[:TYPE*2]->()        — ровно 2 шага
()-[:TYPE*1..3]->()     — от 1 до 3 шагов
()-[:TYPE*]->()         — любое количество шагов (опасно!)
()-[:TYPE*0..3]->()     — 0..3 шагов (включая сам узел)
()-[:TYPE1|TYPE2*1..3]->() — любой из типов рёбер
```

### 9. Паттерны с фильтрацией на каждом шаге

```cypher
// Цепочка LEADS_TO где каждое промежуточное действие — "mechanism"
MATCH path = (start:Action)-[:LEADS_TO*1..5]->(end:Action)
WHERE all(r IN relationships(path) WHERE r.status = "confirmed")
  AND all(n IN nodes(path)[1..-1] WHERE n.action_class = "mechanism")
RETURN 
    [n IN nodes(path) | n.label_text] AS chain,
    [n IN nodes(path) | n.action_class] AS classes,
    length(path) AS steps
```

```cypher
// Цепочка синтаксических зависимостей только через существительные
MATCH path = (start:LexicalUnit {lemma:"mtor"})
             -[:DEPENDS_ON*1..4]->(end:LexicalUnit {pos:"NOUN"})
WHERE all(n IN nodes(path) WHERE n.pos = "NOUN" OR n.pos = "VERB")
RETURN 
    [n IN nodes(path) | n.text] AS chain,
    [r IN relationships(path) | r.dep_label] AS deps
```

### 10. Сходящиеся паттерны (несколько путей к одному узлу)

```cypher
// Два разных действия приводят к одному последствию
MATCH (a1:Action)-[:LEADS_TO]->(common:Action)<-[:LEADS_TO]-(a2:Action)
WHERE a1.uid < a2.uid  // избегаем дубликатов (a1,a2) = (a2,a1)
RETURN a1.label_text, a2.label_text, common.label_text, count(*) AS cnt
ORDER BY cnt DESC
LIMIT 20
```

```cypher
// Три действия сходятся в одном: A→D, B→D, C→D
MATCH (a1:Action)-[:LEADS_TO]->(d:Action)
      <-[:LEADS_TO]-(a2:Action)
      <-[:LEADS_TO]-(a3:Action)
WHERE a1.uid < a2.uid AND a2.uid < a3.uid
RETURN 
    [a1.label_text, a2.label_text, a3.label_text] AS sources,
    d.label_text AS target
```

### 11. Расходящиеся паттерны (один узел → много последствий)

```cypher
// Действие, которое запускает наибольшее число последствий
MATCH (start:Action)-[:LEADS_TO*1..3]->(end:Action)
RETURN start.label_text, count(DISTINCT end) AS reach
ORDER BY reach DESC
LIMIT 10
```

```cypher
// Глагол, от которого зависит больше всего существительных
// (через произвольные цепочки зависимостей)
MATCH (v:LexicalUnit {pos:"VERB"})-[:DEPENDS_ON*1..3]->(n:LexicalUnit {pos:"NOUN"})
RETURN v.lemma, v.text, count(DISTINCT n) AS noun_reach
ORDER BY noun_reach DESC
LIMIT 20
```

### 12. Циклические паттерны (обратные связи)

```cypher
// Найти циклы в LEADS_TO: A → B → ... → A
MATCH path = (a:Action)-[:LEADS_TO*2..5]->(a)
RETURN 
    [n IN nodes(path)[0..-1] | n.label_text] AS cycle,
    length(path) AS cycle_length
LIMIT 10
```

> ⚠️ **Замечание:** Циклы в LEADS_TO — это аномалия. DAG-фильтрация при извлечении должна их исключать. Если циклы найдены — это ошибка данных.

### 13. Кросс-документные паттерны

```cypher
// Один и тот же синтаксический паттерн в разных статьях
MATCH (v1:LexicalUnit {pos:"VERB"})-[:DEPENDS_ON {dep_label:"dobj"}]->(o1:LexicalUnit {pos:"NOUN"}),
      (v2:LexicalUnit {pos:"VERB"})-[:DEPENDS_ON {dep_label:"dobj"}]->(o2:LexicalUnit {pos:"NOUN"})
WHERE v1.doc_id <> v2.doc_id
  AND v1.lemma = v2.lemma
  AND o1.lemma = o2.lemma
RETURN v1.lemma, o1.lemma, count(DISTINCT v1.doc_id) AS docs
ORDER BY docs DESC
LIMIT 20
```

```cypher
// Действие из статьи A связано LEADS_TO с действием из статьи B
// (через агрегацию norm_key — одна нода на уникальный паттерн из многих статей)
MATCH (a1:Action)-[r:LEADS_TO]->(a2:Action)
WHERE a1.doc_id <> a2.doc_id
RETURN 
    a1.label_text, a1.doc_count,
    r.relation_subtype,
    a2.label_text, a2.doc_count
ORDER BY a1.doc_count + a2.doc_count DESC
LIMIT 20
```

## Продвинутые техники

### 14. APOC: виртуальные графы и пути

Если установлен APOC Plugin:

```cypher
// Визуализация подграфа вокруг концепта
CALL apoc.path.subgraphAll(
    (start:LexicalUnit {lemma:"mtor"}),
    {
        relationshipFilter: "DEPENDS_ON>",
        maxLevel: 3,
        bfs: true
    }
)
YIELD nodes, relationships
RETURN nodes, relationships
```

```cypher
// Все пути между двумя узлами (не только кратчайший)
MATCH (a:Action {verb:"inhibit"}), (b:Action)
WHERE b.label_text CONTAINS "longevity"
CALL apoc.all.paths(a, b, {maxDepth: 5})
YIELD path
RETURN path, length(path) AS steps
ORDER BY steps
LIMIT 20
```

```cypher
// Группировка паттернов по структуре
MATCH (v:LexicalUnit {pos:"VERB"})-[:DEPENDS_ON]->(o:LexicalUnit {pos:"NOUN"})
WITH v.lemma + "->" + o.lemma AS pattern, count(*) AS cnt
RETURN pattern, cnt
ORDER BY cnt DESC
LIMIT 50
```

### 15. Сравнение лингвистической структуры двух Action

Через Python API (`ActionRepository.compare_actions`):

```python
from adapters.repositories.action_repository import ActionRepository

repo = ActionRepository()
result = repo.compare_actions("uid-action-1", "uid-action-2")

print("Общие леммы:", result["common_lemmas"])
print("Уникальны для 1:", result["unique_to_1"])
print("Уникальны для 2:", result["unique_to_2"])
print("Схожесть Jaccard:", result["jaccard_similarity"])
print("Общие паттерны:", result["common_dep_patterns"])
```

### 16. Статистика лингвистического графа

```python
from adapters.repositories.action_repository import ActionRepository

repo = ActionRepository()
stats = repo.get_lexical_graph_stats()

print("Всего токенов:", stats["total_units"])
print("Уникальных лемм:", stats["unique_lemmas"])
print("POS-распределение:", stats["pos_distribution"])
print("Dependency-распределение:", stats["dep_distribution"])
print("Рёбра DEPENDS_ON:", stats["edge_distribution"])
```

## Рецепты: готовые запросы для типовых задач

### «Кто/что ингибирует mTOR?»

```cypher
MATCH (v:LexicalUnit {lemma:"inhibit"})-[:DEPENDS_ON {dep_label:"dobj"}]->(o:LexicalUnit {lemma:"mtor"})
OPTIONAL MATCH (s:LexicalUnit)-[:DEPENDS_ON {dep_label:"nsubj"}]->(v)
RETURN s.lemma AS inhibitor, v.text AS verb, o.text AS target
```

### «Какие цепочки ведут к продлению жизни?»

```cypher
MATCH path = (start:Action)-[:LEADS_TO*1..5]->(end:Action)
WHERE end.label_text CONTAINS "longevity"
  OR end.label_text CONTAINS "lifespan"
RETURN 
    [n IN nodes(path) | n.label_text] AS chain,
    length(path) AS steps
ORDER BY steps
LIMIT 30
```

### «Какие прилагательные чаще всего модифицируют senescence?»

```cypher
MATCH (adj:LexicalUnit {pos:"ADJ"})-[:DEPENDS_ON {dep_label:"amod"}]->(n:LexicalUnit {lemma:"senescence"})
RETURN adj.lemma, adj.text, count(*) AS cnt
ORDER BY cnt DESC
```

### «Найти все SVO паттерны с глаголом activate»

```cypher
MATCH (s:LexicalUnit)-[:DEPENDS_ON {dep_label:"nsubj"}]->(v:LexicalUnit {lemma:"activate"})
      -[:DEPENDS_ON {dep_label:"dobj"}]->(o:LexicalUnit)
RETURN s.lemma, v.text, o.lemma, v.doc_id
ORDER BY v.doc_id
```

### «Какие действия связаны с наибольшим числом других действий?»

```cypher
MATCH (a:Action)-[:LEADS_TO]->(other:Action)
RETURN a.label_text, count(DISTINCT other) AS out_degree
ORDER BY out_degree DESC
LIMIT 10
```

### «Показать все зависимые слова от глагола, включая косвенные»

```cypher
MATCH path = (v:LexicalUnit {lemma:"inhibit", pos:"VERB"})
             -[:DEPENDS_ON*1..3]->(dep:LexicalUnit)
WHERE NOT ()-[:DEPENDS_ON]->(v)  // v — корень
RETURN 
    v.text AS verb,
    [n IN nodes(path)[1..] | n.text] AS dependents,
    [r IN relationships(path) | r.dep_label] AS dep_types,
    length(path) AS depth
```

## Производительность

### Индексы

Neo4j автоматически индексирует `:LexicalUnit(lemma)`, `:LexicalUnit(pos)`, `:LexicalUnit(dep)`, `:Action(verb)`, `:Action(norm_key)`. Проверить:

```cypher
SHOW INDEXES
```

### Оптимизация запросов переменной длины

| Приём | Зачем |
|-------|-------|
| `*1..N` вместо `*` | Всегда указывайте верхнюю границу |
| `shortestPath()` | Вместо полного перебора путей |
| `LIMIT` | Ограничивайте результат |
| Фильтрация в `WHERE` до `MATCH` | Сужайте стартовый набор узлов |
| `bfs: true` в APOC | BFS быстрее DFS для поиска путей |

### Когда запрос медленный

```cypher
// ПЛОХО: неограниченная глубина, нет WHERE
MATCH path = (a)-[:LEADS_TO*]->(b) RETURN path

// ХОРОШО: ограничение глубины + фильтр
MATCH path = (a:Action {verb:"inhibit"})-[:LEADS_TO*1..5]->(b:Action)
WHERE b.action_class = "result"
RETURN path
LIMIT 50
```

## Справочник dependency labels (spaCy)

| `dep_label` | Значение | Пример |
|-------------|----------|--------|
| `nsubj` | Подлежащее (актив) | **Rapamycin** inhibits |
| `nsubj:pass` | Подлежащее (пассив) | **mTOR** is inhibited |
| `dobj` / `obj` | Прямое дополнение | inhibits **mTOR** |
| `amod` | Определение (прилаг.) | **cellular** senescence |
| `compound` | Составное существительное | mTOR **signaling** |
| `advmod` | Обстоятельство | **strongly** inhibits |
| `neg` | Отрицание | does **not** inhibit |
| `xcomp` | Открыое дополнение | causes [cells **die**] |
| `advcl` | Обстоятельственная придат. | inhibits mTOR, [**preventing** growth] |
| `ccomp` | Дополнение-придат. | shows [**that** mTOR inhibits] |
| `conj` | Однородный член | inhibits and **prevents** |
| `prep` | Предлог | inhibition **of** mTOR |
| `pobj` | Объект предлога | of **mTOR** |
| `relcl` | Определительная придат. | mTOR, [**which** regulates] |

# Два независимых способа построения карты статьи

На вкладке «Карта статьи» доступны «Текст → карта знаний» и «Структурные строки → карта знаний».
Список версий содержит последний успешный результат каждого способа. Повторное построение
обновляет только соответствующую карту. Ошибка или отмена не удаляет предыдущую карту.

Новый маршрут `text_reified` читает сохранённый полный английский Markdown непосредственно
из S3. Он не вызывает NLP, извлечение структурных строк или старый построитель. Промпт
`KM.TEXT_TO_MAP`, версия 2, находится в `api/application/text_to_map.en.md` и содержит
145 пересмотренных правил модели самостоятельных знаний. Модель выбирается существующей ролью
`article_extraction`; адрес AI-сервиса и ограничения контекста берутся из штатной конфигурации.
Первому этапу передаётся полный JSON Schema ответа с `strict=true` через штатный AI-сервис.
Второй этап также использует `strict=true`: закрытая схема содержит массив направленных пар
с обязательными полями и исчерпывающим enum способов использования знаний.
Все смысловые инварианты дополнительно проверяются сервером. Научные qualifiers представлены закрытым объектом `attributes`
с записями `name`, `value`, `unit`: имена остаются свободными строками, числовые значения
сохраняют числовой тип, сложные ограничения записываются точным английским текстом.
Первый этап обязан вернуть пустые входы и стрелки.
Обязательные поля, формат и все инварианты строго проверяет сервер;
пропущенные поля не дополняются автоматически, неверный ответ отклоняется целиком.
Именованные понятия, объекты, классы и свойства переиспользуются в скрытом словаре `concepts`.
Видимые блоки выражают самостоятельные определения, утверждения, наблюдения, правила,
методы, конкретные применения методов, результаты, сравнения, выводы, состояния, действия
и цели. Название стандарта или критерия само по себе не становится видимым правилом.
References исключается из извлечения, но полный источник сохраняется вместе с результатом.

Граф новой карты имеет `schema_version=5`. Узлы содержат естественный английский текст,
вид знания, aliases, скрытую семантику с ролями участников и provenance. Связи содержат
только `source` и `target`. Сервер проверяет контракт и DAG и вычисляет ранги слева направо.
Роли участников ссылаются на словарь либо на знания и не создают стрелок. Непосредственные
входы знаний объявляются в `semantic.inputs`: идентификатор знания, способ использования,
конкретное объяснение и source unit_ids. Каждая стрелка должна точно соответствовать одному
такому входу; участники словаря не являются концами стрелок. Неизвестные ссылки,
необоснованные по контракту стрелки, дубли и циклы отклоняются целиком.
Независимые факты могут оставаться без связей; минимальное число слоёв не задаётся.
Сервер сохраняет глубину, распределение блоков по слоям и число операций в `graph.analysis`.

Второй обязательный этап использует английский промпт `KM.TEXT_TO_MAP.DEPENDENCIES`,
версия 14, в `api/application/text_to_map_dependencies.en.md`. Он получает полный источник
и извлечённую карту, затем строит и проверяет полный набор зависимостей между знаниями, включая
зависимости между абзацами. Этап меняет только входы и стрелки: создавать, удалять или
переписывать знания ему запрещено. Все вызовы используют `article_extraction`; лимиты
контекста проверяются перед каждым вызовом. У второго ответа отдельная строгая JSON Schema.
`dependencies` — полный массив направленных пар с явными полями `source`, `target`, `usage`, `reason`, `unit_ids`. Оба конца — короткие рабочие id соответствующих текстов. Сервер сохраняет все извлечённые блоки, включая не упомянутые в связях, и переносит проверенные пары в `semantic.inputs`. Пустой массив означает отсутствие связей, а не пустую карту.
Целевые блоки проверяются заранее определёнными непересекающимися группами по 40, последняя
группа может быть меньше. Каждому запросу передаются полный текст, вся неизменная извлечённая
карта, уже проверенные связи, завершённые цели и текущий список `dependency_target_keys`.
Источник новой связи может быть любым блоком всей карты, включая следующую группу;
группы не задают научное направление или ранги. Scoped-схема содержит `anyOf` из отдельных
ветвей на каждую цель: `target` фиксирован через `const`, а `source` разрешён конечной
regex-альтернативой остальных известных id. Самоссылка и обратный вход от уже известного
потомка цели запрещены до генерации. Циклы между новыми связями дополнительно проверяются
доменным валидатором полного объединения.
Общий enum usage не размножается; unsupported `not`, `if`, `allOf` не используются.
После каждой группы проверяется DAG объединения, а перед сохранением — полный граф и
охват всех блоков. Ошибка не приводит к публикации частичной карты. Это штатный алгоритм,
а не автоматическое переключение после отказа. Модель и `reasoning_effort=max` сохранены.
Проверенные ответы отдельных групп переиспользуются только при точном совпадении запроса,
включая все ранее принятые связи. Метаданные результата содержат точные вызовы `batches`
и суммарный usage; журнал затрат учитывает каждый реальный вызов один раз.
Каждая запись содержит `source` и `target` (строки с рабочими ключами текстов), `usage`,
`reason`, `unit_ids`. Независимые блоки не требуют пустых записей в массиве.
В каждой scoped-ветви разрешены только известные ключи текстов, отличные от выбранной цели.
Полные тексты не размножаются внутри схемы. Общий usage объявляется через `$ref`.
Размер зависит от числа блоков и текущих целей; источники всех групп остаются доступными.
Ключи обоих концов однозначно переводятся в исходные id на сервере. Изменение схемы
инвалидирует прежние групповые ответы даже при неизменном промпте; они остаются в архиве.
Повтор JSON-ключа отклоняется парсером, повтор направленной пары — доменным валидатором;
прежние контракты с объектами source, полями target_text_key и списками смежности
не принимаются новым вызовом. Схема формируется
из извлечённых блоков; сервер связывает ключи с точными текстами внутри данной ревизии. Номера абзацев не могут
заменять ключи текстов блоков. Сервер дополнительно сверяет концы
и проверяет, что обоснование включает источник одного из концов зависимости.
Дополнительные существующие абзацы статьи могут обосновывать контекст применения;
полностью постороннее обоснование и ссылки за пределы статьи отклоняются.
В сохраняемом графе концы связей по-прежнему являются только идентификаторами.
Во входной рабочей карте id `T1`, `T2` и далее прикреплены непосредственно к полным текстам знаний.
Ссылки на знания используют те же рабочие id; словарь отделён пространством `C:`.
Сервер переводит результат в прежние хранимые id. Все тексты, aliases, роли, ограничения
и исходные координаты сохраняются. Контраст независимых фактов не создаёт взаимных входов;
цель исследования сама по себе не обосновывает численные данные.
Сервер передаёт готовый словарь `knowledge_text_keys` с короткими ключами `T1`, `T2` и далее,
а модель копирует значения. Они привязаны к полным текстам сортировкой внутри точной карты;
порядок блоков и номера абзацев не определяют эти ключи. Полные тексты остаются во входной карте,
а хеши всего источника, запроса и ответа сохраняются отдельно. Ключи не становятся блоками графа.
При `response.incomplete` AI-сервис передаёт безопасную причину отказа и доступный usage,
включая reasoning tokens. Неполный ответ не принимается и автоматически не повторяется.
Ошибка или отмена любого этапа сохраняет предыдущий успешный результат. Lease блокировки
продлевается перед каждой LLM-группой и перед сохранением, только при действующем токене
своего запуска. Истёкшая или чужая блокировка отклоняется. Хеши обоих промптов и метаданные
всех вызовов сохраняются отдельно. Порядок абзацев, совпадение участников и причинные отношения
реального мира сами по себе не являются входами знаний.

Сохранённые карты схемы 4 читаются прежним адаптером, без миграции и пересборки.
Новый вызов принимает только схему 5; переключения на старый контракт при ошибке нет.
Успешная пересборка обновляет только слот `text_reified`, согласно политике одного
последнего результата на пайплайн. Карта `structural_rows` остаётся независимой.
Эти технические проверки не подтверждают научную точность извлечения.

Каноническая карта всегда английская. Переключатель русского языка создаёт и сохраняет
отдельный перевод подписей для конкретного `run_id`; связи и семантика не переводятся
и не изменяются. Новое построение сбрасывает перевод предыдущего результата.

API относительно `/api/article_editor/articles/{doc_id}/maps`:

- `GET /` — две сохранённые карты и доступность входов.
- `GET /{pipeline_id}?locale=en|ru` — выбранная карта.
- `POST /text_reified/build` — SSE: `start`, `progress`, `result`, `error`, `cancelled`.
- `POST /structural_rows/build` — детерминированное построение без LLM.
- `POST /{pipeline_id}/translate` — отдельный русский перевод через SSE с keep-alive.
- `GET /{pipeline_id}/provenance/{node_id}` — исходные фрагменты новой карты.

Каждая операция проверяет владельца статьи. Neo4j хранит один `ArticleMap` на пару
`(article_id,pipeline_id)`. Межпроцессная блокировка и lease запрещают одновременные
запуски одного способа для одной статьи; разные способы независимы. На старте API
создаётся constraint и идемпотентно переносятся существующие deterministic snapshots.
Исходные snapshots, версии извлечения и GOLD-эталоны сохраняются.

После установки изменений пользователь перезапускает API и обновляет клиент.
Порты сервисов остаются прежними. CLI запускается с правами администратора.

Для первой GOLD-статьи из каталога `api`:

```powershell
poetry run python tools/run_text_to_map_gold.py --article-id gold-pmc10000452
```

Для изолированной GOLD-копии передаётся её точный идентификатор. Скрипт проверяет
соответствие `PMC10000452` и хешу неизменяемого английского источника до вызова LLM,
сохраняет новую карту в Neo4j и проверяет сохранность карты из структурных строк.
Эталонные файлы не перезаписываются.

Для явного продолжения после успешного извлечения CLI поддерживает
`--extraction-checkpoint <путь к ответу первого этапа>`. Это административная операция:
API всегда выполняет оба этапа. Контрольная точка содержит отдельный файл метаданных
с хешами полного источника, промпта, точного запроса и ответа, а также исходные сведения
о модели. Все привязки проверяются, ответ повторно проходит доменную валидацию,
а второй этап выполняется заново через настроенный AI-сервис. Несовпадение отклоняется;
автоматического восстановления или замены модели нет. Метаданные сохранённого результата
явно отмечают повторное использование ответа. `--response-artifact <путь>` сохраняет
неизменённые ответы обоих этапов и их метаданные для диагностики.

Каталог эталонов задаётся `ARTICLE_PIPELINE_GOLD_DIR`; production-образ API уже задаёт
`/data/article_pipeline_gold`. Оба промпта явно разрешены в `.dockerignore` и поставляются
вместе с доменными модулями API через Docker `COPY . .`.

## English

The article map tab provides two independent pipelines: direct text-to-map extraction
using the project's configured LLM, and deterministic structural-rows-to-map building.
Each pipeline retains one successful map per article. Rebuilding one never overwrites
the other. The new prompt and canonical output are English; Russian labels are a separate
translation tied to the successful run. Technical DAG and provenance validation does
not constitute expert scientific review.

Version 2 uses schema 5: visible nodes are independent knowledge, while canonical concepts
are a hidden participant dictionary. Participant roles never create edges. Edges correspond
exactly to source-grounded, justified knowledge inputs. A required second LLM stage reviews
the complete dependency set against the full source without changing knowledge content.
Stored schema 4 maps remain readable until a successful rebuild replaces that pipeline's slot.
Dependency endpoints are constrained to exact extracted identifier/text pairs, then checked
against endpoint provenance. An explicit administrative extraction checkpoint verifies
source, prompt, request and response hashes before reuse; dependency generation always runs
again through the configured service. Reuse is recorded in the saved model metadata.
The first GOLD article, PMC10000452, was saved with schema 5 on 2026-10-04:
131 visible knowledge nodes, 154 edges, 12 layers, 228 hidden concepts, and 18 operations.
The persisted result passed independent contract, DAG and provenance checks; the structural
map and GOLD references were unchanged. This is technical validation, not expert review.

Отклонённые кандидаты не включаются в массив принятых входов. Каждая запись создаёт действующее ребро; обоснование, отрицающее саму зависимость, не отменяет эту запись. Отрицательный научный факт может быть полноценной предпосылкой. Циклический ответ отклоняется целиком; исходный ответ и предыдущая успешная карта сохраняются.

В исторической версии 12 каждый целевой блок имеет строго именованный объект `inputs`: это входящие предпосылки, а не исходящие применения знания. Например, индивидуальные измерения двух исследований подаются на их объединённую оценку только в её `inputs`. Обратные записи требуют отдельного обоснования и не создаются зеркально. Все целевые ключи обязательны; блок без входов имеет `{"inputs":[]}`.

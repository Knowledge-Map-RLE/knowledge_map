# Определение знания и алгоритм уникальности

> Дата: 13 апреля 2026 г.
> Контекст: анализ проекта "Карта Знаний" (Knowledge Map)

---

## 1. Определение "Знания"

### Формальное определение

> **Знание** — это *минимальный связный направленный подграф* лингвистического графа, представляющий причинно-следственную связь между двумя и более действиями (`Action`), где:
>
> 1. **Неполнота (epistemic gap)**: мы фиксируем, что B ведёт к A, но не утверждаем полноту условий — B может быть необходимым, но недостаточным для A, или достаточным, но не единственным.
> 2. **Направленность**: рёбра `LEADS_TO` образуют DAG — нет циклов, есть причинное направление.
> 3. **Минимальность**: знание не разлагается на меньшие независимые причинные связи без потери смысла.

### Уровни гранулярности знаний

| Уровень | Что является знанием | Пример |
|---|---|---|
| **L1: Атомарное** | Одно ребро `LEADS_TO` между двумя Action | "Rapamycin → inhibits → mTOR" |
| **L2: Цепочка** | Путь из 2+ рёбер `LEADS_TO` | "Rapamycin → mTOR → ↓cell growth → ↑lifespan" |
| **L3: Паттерн** | Изоморфный подграф, встречающийся в разных документах | "X inhibits Y → Z decreases" (абстрагированный) |
| **L4: Блок-связь** | `Block → LINK_TO → Block` на уровне визуализации | Высокоуровневая карта понятий |

Гипотеза: базовый уровень знания — **L1**, атомарная причинная связь между парой действий.

## 2. Алгоритм уникальности знаний

### Задача

Дано новое знание K (подграф). Проверить, нет ли уже в системе эквивалентного. Если дубликат найден — отбросить. Если нет — считать знание новым и сохранить.

### Проблема

**Изоморфизм подграфов — NP-полная задача** в общем случае. Однако наш граф имеет структуру, которую можно использовать для оптимизации.

### Многоуровневый алгоритм (от быстрого к точному)

```
Algorithm: UniquenessCheck(K_new)
Input:  K_new — новый подграф (знание)
Output: UNIQUE | DUPLICATE(existing_uid)
```

#### Stage 1: Хеш-фильтр — O(1)

1. Нормализовать узлы: `(lemma, pos, dep_role)` → каноническая форма.
2. Построить каноническое представление графа:
   - Упорядочить узлы топологически.
   - Для каждого узла: `(role, normalized_tokens_sorted)`.
   - Сериализовать в байты.
3. Вычислить `SHA256` от сериализации.
4. Проверить наличие hash в индексе.
   - **Если найден → DUPLICATE.**
   - **Иначе → Stage 2.**

#### Stage 2: Сигнатурный фильтр — O(log N)

Вычислить инварианты подграфа:
- Число узлов каждого типа (Action, LexicalUnit).
- Число рёбер каждого типа (`LEADS_TO`, `DEPENDS_ON`).
- Degrees in/out distribution.
- Depth (longest path length).
- Action class multiset.

Найти кандидатов по инвариантам (B-tree индекс).
- **Если кандидатов 0 → UNIQUE.**
- **Иначе → Stage 3.**

#### Stage 3: Структурное сравнение — O(k · |V_K|²)

Для каждого кандидата C:
1. Проверить изоморфизм с учётом меток (label-aware):
   - Топологическая сортировка обоих DAG.
   - Поуровневое сопоставление узлов по ролям.
   - Проверка совпадения рёбер.
2. Если изоморфен → проверить семантическую эквивалентность:
   - Сравнить `norm_key` для каждого спаренного Action.
   - Если все `norm_key` совпали → **DUPLICATE**.
3. Если не изоморфен → следующий кандидат.

**Если все кандидаты отвергнуты → UNIQUE.**

## 3. Big O анализ

| Stage | Сложность | Пояснение |
|---|---|---|
| **Stage 1** | **O(1)** | Хеш-lookup в HashMap |
| **Stage 2** | **O(log N)** | Поиск по B-tree индексу инвариантов |
| **Stage 3** | **O(k · \|V_K\|²)** | k — число кандидатов, \|V_K\| — узлов в новом знании |

### Худший случай

`O(N · |V_K|²)` — если все N знаний имеют одинаковые инварианты (практически невозможно при хороших инвариантах).

### Средний случай

`O(log N + k · |V_K|²)` где `k << N` (обычно k = 0..5).

### Почему это надёжно

1. **Stage 1** отбрасывает точные дубликаты мгновенно.
2. **Stage 2** отсекает >99% графа по структурным инвариантам.
3. **Stage 3** делает точное сравнение только с горсткой кандидатов.

## 4. Дубликаты vs переформулировки

| Тип | Структура | Семантика | Вердикт |
|---|---|---|---|
| **Точный дубликат** | Та же | Та же | Отбросить |
| **Переформулировка** | Та же | Другие lemma/tokens | Новое знание (может линковаться через Pattern) |
| **Расширение** | Больше узлов/рёбер | Частично перекрывается | Новое знание |
| **Специализация** | Та же структура | Более конкретные terms | Новое знание |

`Pattern` абстрагирует структуру от конкретных слов. Новый экземпляр паттерна ≠ новое знание на уровне структуры, но может быть новым на уровне семантики.

## 5. Рекомендации по реализации

1. **`norm_key` в Action** — уже есть SHA256 хеш. Использовать его как основу для Stage 1.
2. **Индекс инвариантов** — добавить в Neo4j constraints/indexes на `(depth, n_actions, n_edges, action_classes_hash)`.
3. **Canon_hash для подграфа** — функция, которая берёт набор Action UID'ов, вытаскивает подграф, нормализует и хеширует.

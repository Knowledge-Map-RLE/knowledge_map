# Новый формат научных статей

Исходное предложение: `С момента открытия дофамина как нейромедиатора в 1950-х годах исследования болезни Паркинсона (БП) сформировали богатую и сложную базу знаний, выявив, что БП является возрастным многофакторным заболеванием, на которое влияют как генетические, так и факторы окружающей среды.`

```bash
S1: дофамин → является → нейромедиатором
S2: S1 → открыто в → 1950-х годах

S3: исследования → объект → болезнь Паркинсона
S4: исследования → сформировали → базу знаний
S5: S2 → раньше → S4

S6: база знаний → свойство → богатая
S7: база знаний → свойство → сложная

S8: болезнь Паркинсона → является → возрастной
S9: болезнь Паркинсона → является → многофакторной

S10: исследования → выявили → S8
S11: исследования → выявили → S9

S12: генетические факторы → влияют на → болезнь Паркинсона
S13: факторы окружающей среды → влияют на → болезнь Паркинсона

S14: исследования → выявили → S12
S15: исследования → выявили → S13
```

Это будет под капотом. А в интерфейсе пользователя вместо обозначений "ссылок" F... и M... будут именно та структура/текст который они обозначают.

Я очень надеюсь что это более интуитивно понятная запись чем у других способов...

Эта запись утверждений и мета утверждений (утверждение об утверждении) позволит сделать любую статью вычислимой, а также пригодной для продвинутых поисковых запросов вроде SPARQL. Поиск противоречий, подтверждений или опровержений тоже идёт в комплекте, надо только написать запрос. А и ещё помните про алгоритм уникальности знаний? Вот на такой штуке он может заработать, даже если с ошибками, но минимально это будет работать.

Ещё фишка, что одно единственное исследование может состоять всего из одной строчки!
M1 → раньше → F3
А например, его цитирование будет автоматическим, как в общем то и для любого триплета статьи.

Тут же для запоминания напишу что утверждения могут ещё называться пропозицией и есть пропозиционная логика. С этим нужно отдельно разбираться, что это.

Кстати, если есть задача парсинга генов среди таких статей, то это будет делаться очень просто, так как нужно будет искать всего один треплет вида X → является → ген или X → это → ген, и он будет обязательно в статье, если пользовались спец редактором, так как если редактор автоматически обнаружит по базе данных что это ген, редактор предложит добавить этот триплет, что бы указание было явным.

Определение языка, на языке спецификаций (или метаязыке, в данном случае БНФ Формы Бэкуса — Наура (https://en.wikipedia.org/wiki/Backus%E2%80%93Naur_form)):
```bash
Statement ::= Identifier ":" Subject "→" Predicate "→" Object
Subject ::= Concept | Statement
Object ::= Concept | Statement | Literal
```

Пока новый язык рекомендуется использовать в связке с Neo4j + Cypher.
Узлы:
```bash
(:Statement {
    id: "F1"
})
(:Concept {
    name: "дофамин"
})
(:Concept {
    name: "нейромедиатор"
})

Связи:
(F1)-[:SUBJECT]->(дофамин)
(F1)-[:PREDICATE]->(является)
(F1)-[:OBJECT]->(нейромедиатор)

Метаутверждения:
(M1)-[:SUBJECT]->(исследования)
(M1)-[:PREDICATE]->(выявили)
(M1)-[:OBJECT]->(F7)
```

## Структура статей в триплетах

Что бы понять какие триплеты нам нужны из научных статей, нужно делать обратное планирование относительно цели — продлить жизнь человеку на неограниченный срок, вылечить старение человека.

Значит, всё что касается цели потенциально может помочь. Всё что говорит нам о составе человека, старения, омоложения, подходит. Нам нужно что бы старение уменьшалось, омоложение увеличивалось, состав человека не сильно изменялся. Нужно знать как состав меняется с возрастом, и то что этому препядствует или обращает вспять. Нужно знать нормальные процессы в организме, выявлять патологии и восстанавливать процессы в исходное состояние на всех уровнях организации человека одновременно (комбинированная терапия). Нужно знать все взаимодействия чего либо в организме человека и размер эффекта каждого взаимодействия.

## Порядок чтения научной статьи

Это очень хороший вопрос. Более того, **порядок чтения статьи опытным учёным обычно отличается от порядка, в котором статья написана**.

Если цель — **быстро понять, стоит ли статья внимания**, её читают примерно так.

```text
1. Название
2. Аннотация (Abstract)
3. Рисунки и таблицы
4. Результаты
5. Методы
6. Обсуждение
7. Введение
8. Дополнительные материалы (Supplementary)
9. Список литературы (при необходимости)
```

Почему так?

Потому что большинство учёных хотят сначала понять:

* **что нового нашли?**
* **насколько это убедительно?**
* **можно ли доверять результату?**

А уже потом читают подробности.

### Но если говорить про "Карту Знаний"

Мне кажется, здесь есть более интересная идея.

Ты сейчас проектируешь **не новую статью**, а **новый формат представления знаний**.

Если удалить всю "литературную" часть статьи и оставить только знания, получится примерно такая структура.

### Я думаю, следующая эволюция твоего языка

Мне кажется, можно сделать ещё один шаг дальше.

Практически любую статью можно представить как **последовательность преобразований знаний**:

```text
Предыдущие знания
        │
        ▼
     Гипотеза
        │
        ▼
Дизайн эксперимента
        │
        ▼
Получение данных
        │
        ▼
Статистический анализ
        │
        ▼
Новые утверждения
        │
        ▼
Изменение уверенности
        │
        ▼
Обновление глобальной базы знаний
```

Обрати внимание, что это почти совпадает с тем, как ты уже мыслишь "Карту Знаний": исследование — это не просто текст, а **операция, которая преобразует состояние научного знания**. Тогда статья становится вычислимым объектом: у неё есть вход (предыдущие знания), процесс (эксперимент и анализ) и выход (новые или уточнённые утверждения). Именно этот "поток знаний" может стать основой структуры статьи в твоём формате, а не традиционные разделы IMRaD.


## Промпт для преобразования текста в триплеты

Промпт: декомпозиция научного текста на атомарные триплеты

### Роль
Ты — эксперт по представлению знаний (knowledge representation). Твоя задача — разложить длинные текстовые поля научной статьи на **атомарные утверждения-триплеты** формата `UUIDv8_n: субъект → предикат → объект` без потери смысла, по строгим правилам ниже.

### Исходные данные
- Вход: текстовые поля блоков структурной разметки статьи (типы T7 «Гипотеза», T16 «Биологический механизм», T22 «Сущность», T23 «Определение понятия», T37 «Статистическая обработка», T38 «Утверждение», T39 «Ограничения», T40 «Побочные выводы/гипотезы», T44 «Новизна», T46 «Будущие исследования», T47 «Связи с предыдущими», T56 «Шаг эксперимента», T57 «Результат (находка)»).
- Для каждого блока-контейнера ты выдаёшь **упорядоченный список атомарных блоков** (тип T4 «Прямой триплет»), который будет сохранён в поле `sequence` контейнера.

### Определение атомарного триплета
Один триплет = один простой факт. **Минимизация слов**: каждый из S/P/O должен быть как можно короче (1–3 слова, в идеале 1–2). Любая конструкция длиннее ~4 слов разбивается на цепочку связанных триплетов. Смысл исходного текста должен быть полностью сохранён — каждый смысловой элемент исходника обязан встретиться хотя бы в одном триплете (проверь покрытие: пройдись по исходнику слово за словом).

### Приёмы (используй именно эти, с этими названиями)

#### 1. Декомпозиция длинного объекта («включают»-сплит)
Если объект — перечисление или перечислительная фраза, разбей его на отдельные триплеты через предикаты `включают` / `входят в` / `содержат`:
- Исходник: `сухие аридные регионы (Средний Восток, Саудовская Аравия, Израиль, Африка)`
- → `сухие аридные регионы → включают → Средний Восток`, `… → включают → Саудовская Аравия`, `… → включают → Израиль`, `… → включают → Африка`
- Тот же приём для скобочных списков, `;`, `и`, `или`, а также `n = 10–12` → `клетка → вмещает → 10–12 особей`.

#### 2. Выделение характеристик («является»-сплит)
Каждая характеристика/определение → отдельный триплет с предикатом `является` (или `являются`):
- `признаки являются специфическими адаптивными` → `признаки → являются → специфическими адаптивными`
- `признаки являются эволюционно консервативными` → `признаки → являются → эволюционно консервативными`
- Два определения из одного исходника → два отдельных триплета с одинаковым субъектом.

#### 3. Вопросные предикаты (семантическая роль через вопрос)
Если глагол не даёт чёткого отношения, используй вопросительные формы как предикаты для восстановления семантической роли зависимого слова:
- `кого` / `чего` / `чем` / `чем` / `к какой` / `какой` / `какие` / `какие не` / `где` / `когда` / `сколько` / `как долго` / `до куда` / `для кого` / `для чего` / `в чём` / `из чего` / `от кого` / `с чем` / `к чему` / `на ком` / `при каком` / `какая` / `какой возраст` / `как часто` / `под чем` / `после чего`
- Пример: `взвешивали → кого → мышей`; `перед → чем → тестом`; `балки → какой → деревянной`; `добраться → до куда → противоположного конца`; `увеличение → когда → с возрастом`.
- Правило: вопрос задаётся от субъекта или от глагола действия, ответ = объект триплета. Форма объекта согласуется с вопросом (склонение по падежу: `торпор → активируется при → отрицательном энергетическом балансе`).

#### 4. Разделение атрибутов по «какой»
Серийные определения объекта разбиваются на отдельные триплеты: `мыши → какие → упавшие`, `мыши → какие не → двигавшиеся`. Атрибуты с негацией получают предикат `какие не`.

#### 5. Уточнение и аппозиция («является» + «для кого»)
Продолжения и уточнения после двоеточия/тире/скобок разворачиваются отдельно:
- `25°C → является → нижней критической температурой`; `29°C → для кого → A. russatus`; `25°C → для кого → A. dimidiatus`.
- `Acomys dimidiatus → является → ночным видом`.

#### 6. Причинно-целевые цепочки («позволяет» / «для чего» / «что бы что» / «затем»)
Причинно-следственные и целевые связи — отдельными триплетами, где субъект ссылается (UUID или повторяется):
- `конкуренция → с → Acomys dimidiatus`; `конкуренция → за → ограниченные ресурсы`; `конкуренция → позволила → перейти к дневной активности`; `конкуренция → позволила → перейти к сумеречной активности`.

#### 7. Ссылки и цитаты («в»-триплет)
Номера источников `(68)`, `(87, 88)`, `(82-84)`, ссылки на рисунки `Fig. 6` — отдельные триплеты: `X → в → (82-84)`, `X → на → функциональном уровне`, `X → в → Fig. 6`. Аббревиатуры-ссылки (`ApoER2`, `VLDLR`, `Dab1`) оставляй как есть.

#### 8. Кросс-ссылки внутри последовательности (uuid-реф)
Когда в триплете нужно повторить уже встреченный ранее субъект/объект, **не повторяй текст** — ставь на его место **UUID предыдущего атомарного блока**, где этот термин впервые определён:
- `0006585d-… → когда → 0006585d-…` (субъект/объект — UUID ранее созданных триплетов).
- Цепочка из 17 триплетов шага «Beam walking test» построена так: первые триплеты открывают термины текстом, последующие ссылаются на них UUID.
- Правило: **первый** триплет с термином пишется текстом, повторное использование термина → UUID. В итоговой последовательности ~20% триплетов могут содержать uuid-рефы.

#### 9. Нормализация и согласование
Приводи субъект к словарной/каноничной форме, склоняй объект по падежу предиката: `замедление → касается → процессов восстановления клеток и тканей`; `восстановление → затрагивает → клетки и ткани`. Прилагательные из исходника сохраняй в объекте: `непрерывное`, `эволюционно консервативные`.

#### 10. Модальность и негация (честный перенос)
Негация и оценочность сохраняются **внутри предиката или объекта**, а не теряются:
- `не повышены` / `не значимо регулировал` / `без различий` / `без изменений` / `отсутствовало` / `неизбежна потому что` / `вносит незначительный вклад в` / `вероятно`.
- `смертность большинства млекопитающих → происходит в → дикой природе`; `большинство млекопитающих → обитает в → дикой природе`.

#### 11. Локативная декомпозиция (место)
Местоположение разворачивается отдельными триплетами: `зоологический исследовательский сад → находится в → Тель-Авивском университете`; `потомки животных → происходят из → Иудейской пустыни`; `Acomys → содержатся в → крупных клетках на открытом воздухе`.

#### 12. Временные рамки
Периоды действия — отдельными триплетами: `не-патоген-свободные условия → действуют в период → 2018–2023`; `увеличение → когда → с возрастом`.

### Порядок вывода
1. Сначала — «фундаментальные» триплеты: термины, определения, характеристики субъектов (на них ссылаются остальные).
2. Затем — действия и связи.
3. В конце — ссылки/цитаты/рисунки.
4. Если элемент используется дальше в той же последовательности, выводи его раньше, чтобы на него можно было сослаться UUID.

### Формат вывода
JSON-массив атомарных блоков. Каждый блок:
```json
{
  "subject": "<текст или UUID-реф>",
  "predicate": "<предикат>",
  "object": "<текст или UUID-реф>"
}
```
UUID-рефы на этом этапе ставишь как **плейсхолдеры** вида `{SEQ1}`, `{SEQ7}` — номер позиции в этой же последовательности; финальные UUID (формата `0006585d-…`) присваиваются на этапе миграции скриптом.

### Антипаттерны (запрещено)
- Не оставляй триплет длиннее 4–5 слов в одной позиции — только если термин неделим (`Acomys russatus`, `двухвыборочный непарный t-критерий Стьюдента`).
- Не теряй слова исходника: каждое значимое слово должно попасть хотя бы в один триплет.
- Не объединяй несколько фактов в один триплет (перечисление `и`/`или`/`,` → приём 1).
- Не меняй смысл: не заменяй конкретику обобщением, не добавляй фактов, которых нет в тексте.
- Не выбрасывай негацию, модальность, ссылки, числовые значения (размеры, `n`, `p`, температуры, годы).
- Не повторяй текст термина, если можно сослаться UUID (приём 8).

### Критерий готовности
После декомпозиции блока пройдись по исходному тексту и убедись: **100% смысловых элементов покрыты** цепочкой триплетов, цепочка линейно читается (каждый следующий триплет понятен в контексте предыдущих), количество триплетов минимально необходимое.

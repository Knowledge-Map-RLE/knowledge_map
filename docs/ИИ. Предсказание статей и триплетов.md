# ИИ. Предсказание статей и триплетов

Да. И я бы здесь разделил задачу на **две независимые задачи**:

1. **Prediction** — может ли Карта Знаний, имея только знания на момент времени `t`, правильно назвать статьи, которые появятся после `t`?
2. **Long-range prediction** — насколько далеко по графу находится реально предсказанная статья от исходной статьи/набора знаний?

При этом есть очень важная тонкость: **для оценки нельзя строить граф на всём датасете сразу**. Иначе алгоритм может случайно использовать информацию из будущего и получится утечка данных.

---

# 1. Что именно мы хотим проверить

Допустим, есть временная последовательность:

```text
2015  Article A
       ↓
2016  Article B
       ↓
2017  Article C
       ↓
2018  Article D
       ↓
2019  Article E
```

Статья `A` содержит:

```text
S1: A → утверждает → X
S2: X → активирует → Y
S3: Y → увеличивает → Z
```

Статья `B`:

```text
S4: B → подтверждает → S1
S5: B → обнаруживает → W
```

и т. д.

В 2015 году алгоритм должен увидеть **только граф, существовавший к концу 2015 года**.

И его задача:

> Какие статьи, появившиеся после 2015 года, с наибольшей вероятностью будут следующими важными продолжениями этого графа?

Например:

```text
Предсказание:

Article C — 0.81
Article D — 0.64
Article F — 0.51
```

А затем через некоторое время мы узнаём, что действительно вышли:

```text
Article C
Article D
```

Получаем проверяемый результат.

---

# 2. Но я бы не предсказывал статью непосредственно

Это, пожалуй, самое важное изменение, которое я бы предложил.

Не:

```text
Article A → Article C
```

а:

```text
Article A
   ↓
утверждения A
   ↓
паттерн
   ↓
предсказанные утверждения
   ↓
статьи, которые могли бы проверить/получить эти утверждения
```

То есть сначала алгоритм должен предсказывать **следующий участок пространства знаний**, а уже потом искать статьи, соответствующие этому участку.

Например:

```text
A:

protein X → activates → pathway Y

B:

pathway Y → increases → inflammation

```

Карта может обнаружить паттерн:

```text
X → activates → Y
Y → increases → inflammation
```

и предсказать:

```text
X → contributes to → inflammation
```

А затем посмотреть:

> Какая будущая статья фактически получила такой результат?

Это гораздо ближе к твоей идее **«предсказать следующий эксперимент»**, чем обычный recommendation engine.

---

# 3. Нужно формализовать статью как множество утверждений

Для статьи `A`:

```text
A = {S1, S2, S3, ..., Sn}
```

где:

```text
S = (subject, predicate, object)
```

Но в твоей системе этого недостаточно, потому что есть метаутверждения.

Например:

```text
S1:
A → утверждает → S2

S3:
Experiment1 → подтверждает → S2

S4:
Experiment1 → опровергает → S5
```

Поэтому фактически статья представляет собой **подграф утверждений**:

```text
Article
   │
   ├── S1
   │    └── S7
   │         └── S12
   │
   ├── S2
   ├── S3
   │    └── S9
   └── S4
```

И именно этот подграф нужно сравнивать между статьями.

---

# 4. Первый фундаментальный алгоритм — нормализация утверждений

Прежде чем искать паттерны, нужно решить проблему:

```text
A → активирует → B
```

и

```text
B is activated by A
```

не должны считаться разными знаниями.

Поэтому нужен канонический вид:

```text
subject = A
predicate = activates
object = B
```

То же касается:

```text
dopamine
Dopamine
DA
3-hydroxytyramine
```

Если это одна сущность, они должны разрешаться в одну canonical entity.

То есть нужен слой:

```text
Raw statement
      ↓
Entity resolution
      ↓
Predicate normalization
      ↓
Canonical statement
```

И только после этого сравнивать статьи.

---

# 5. Второй алгоритм — Statement Similarity

Теперь можно определить:

> Насколько утверждение из статьи A похоже на утверждение из статьи B?

Самый простой вариант:

```text
sim(S1, S2) =
    совпадает субъект
    +
    совпадает предикат
    +
    совпадает объект
```

Например:

```text
S1:
p53 → activates → apoptosis

S2:
p53 → activates → apoptosis
```

```text
similarity = 1.0
```

А:

```text
S1:
p53 → activates → apoptosis

S2:
p53 → inhibits → apoptosis
```

уже:

```text
subject: same
predicate: different
object: same
```

Например:

```text
similarity = 0.67
```

Но здесь появляется очень интересная возможность.

Для твоей системы я бы использовал **структурную similarity**, которая учитывает не только сам триплет, но и его подграф.

---

# 6. Сравнивать нужно не только триплет, а его «контекст»

Допустим:

```text
S1:
A → activates → B
```

В одной статье вокруг него:

```text
C → activates → A
A → activates → B
B → increases → D
```

В другой:

```text
X → inhibits → A
A → activates → B
B → increases → D
```

Само утверждение одинаковое.

Но **структура контекста разная**.

Можно определить:

```text
Neighborhood(S)
```

например на расстоянии `k=2`.

Тогда:

```text
Similarity(S1, S2)
=
similarity(
    canonical statement,
    local statement neighborhood
)
```

Это уже намного более сильный механизм.

# 8. Здесь можно начать без нейросетей

И это очень хорошо соответствует твоему эксперименту.

Можно сделать **rule-based prediction engine**.

Например правило:

```text
ЕСЛИ

A → activates → B
B → activates → C

ТО

кандидат:
A → activates → C
```

Другой паттерн:

```text
A → inhibits → B
B → activates → C

⇒

A → affects → C
```

Но лучше не придумывать произвольные биологические правила.

Пусть правила будут основаны на **исторически обнаруженных паттернах**.

# 9. Mining исторических паттернов

Вот здесь, на мой взгляд, начинается настоящая проверка твоей гипотезы.

Берём старую часть корпуса:

```text
2000–2015
```

и ищем:

```text
паттерн X
    ↓
через 1–5 лет
    ↓
паттерн Y
```

Например:

```text
P1:

A → activates → B

P2:

B → increases → C

```

часто оказывается перед:

```text
P3:

A → increases → C
```

Тогда система запоминает:

```text
P1 + P2
      ↓
P3
```

с некоторой статистикой:

```text

occurrences = 184
successes = 91
precision = 49.5%
```

И это уже **настоящий научный паттерн**, извлечённый из истории литературы.

# 11. Теперь проблема библиографических ссылок

Ты правильно отметил:

> DAG строится не только по зависимости утверждений, но и по библиографическим ссылкам.

Здесь я бы **не смешивал разные типы ребер** в одно.

Например:

```text
Article A ──cites──> Article B
```

это совершенно не то же самое, что:

```text
S1 ──supports──> S2
```

И не то же самое, что:

```text
S1 ──causes──> S2
```

Поэтому граф должен быть **typed DAG / multi-relational graph**.

Например:

```text
Article
   │
   ├── contains ──> Statement
   │
   ├── cites ─────> Article
   │
   └── reports ───> Experiment

Statement
   │
   ├── supports ──> Statement
   ├── contradicts ──> Statement
   ├── causes ─────> Statement
   └── depends_on ─> Statement
```

# 17. Метрика №1 — насколько хорошо предсказываем

Здесь можно использовать обычные ranking metrics.

Например:

### Precision@K

Из первых 10 предсказаний:

```text
10 predictions
3 реально появились
```

получаем:

```text
Precision@10 = 0.3
```

### Recall@K

Если среди всех релевантных будущих статей было 20:

```text
нашли 3
```

то:

```text
Recall@10 = 3 / 20
```

### MRR

Если правильная статья впервые появляется на позиции:

```text
5
```

то:

```text
MRR = 1/5 = 0.2
```

### NDCG@K

Очень полезна, если у тебя есть **степень релевантности**, а не просто:

```text
правильно / неправильно
```

# 18. Но твоя идея требует второй метрики

И вот здесь становится интереснее.

Для каждого successful prediction:

```text
A → predicted Article Z
```

вычисляем:

```text
D(A,Z)
```

Получаем:

```text
prediction     rank     hit     distance
------------------------------------------------
Z              1        ✓       17
X              2        ✓       5
Q              3        ✗       -
Y              4        ✓       11
```

Тогда можно определить:

### Mean Successful Prediction Distance

```text
MSPD =
Σ distance(successful predictions)
/
number of successful predictions
```

Например:

```text
(17 + 5 + 11) / 3 = 11
```

```text
Which Article contains them?
```

Это устранит огромное количество шума.

---

## Я бы сформулировал два главных KPI Карты Знаний так

### KPI-1 — Predictive Accuracy

> **Доля действительно появившихся в будущем релевантных утверждений/статей, которые система смогла предсказать по состоянию графа на момент времени `T`.**

Измеряется через:

```text
Precision@K
Recall@K
MRR
NDCG@K
```

### KPI-2 — Predictive Distance

> **Топологическое расстояние в историческом графе между состоянием знаний, из которого было сделано предсказание, и фактически появившимся предсказанным знанием.**

И здесь я бы обязательно фиксировал **snapshot времени**, чтобы расстояние не использовало информацию из будущего.

---

И тогда появляется очень красивая формулировка всей идеи Карты Знаний:

> **Система должна извлекать из научной литературы структуру знаний, обнаруживать исторические паттерны перехода от одних утверждений к другим и на основе состояния графа в момент `T` предсказывать ещё не появившиеся знания, причём желательно предсказывать их с высокой точностью и на большом топологическом и временном расстоянии.**

Это уже можно превратить в **строго воспроизводимый benchmark для Карты Знаний**, а не просто в субъективное утверждение, что «граф выглядит полезным».

И, на мой взгляд, **именно сейчас имеет смысл остановиться на разработке промпта извлечения утверждений**: качество canonical statements, сущностей, предикатов, метаутверждений и временного/экспериментального контекста будет непосредственно определять потолок этого benchmark.



# ИИ. Реализация проверки двух критериев

Да. Мы обсуждали это как **двухкомпонентный benchmark для самой Карты Знаний**, причём сравнение должно идти **на уровне утверждений, принадлежащих статьям**, а не по текстам статей.

Идея была такой.

## 1. Критерий №1 — насколько хорошо КЗ предсказывает будущую статью

Берём исторический срез базы на момент времени `t`:

```text
G(t) = все знания из статей, опубликованных до t
```

и некоторую предыдущую статью `A`.

Из её утверждений строим **состояние знаний**, доступное системе на тот момент:

```text
A = {S1, S2, ..., Sn}
```

Затем правило-based алгоритм должен найти в существующем графе возможные продолжения:

```text
S1 → S2 → S3 → ... → ?
```

и сформировать **кандидатов будущих статей/утверждений**.

После этого смотрим на реальные статьи, которые появились позже:

```text
A(t)
   ↓
предсказание
   ↓
P1, P2, P3...
   
реальное будущее
   ↓
B(t+1), C(t+2), ...
```

И проверяем, насколько утверждения будущей статьи были предсказаны.

Это по сути близко к задаче **scientific discovery as link prediction**: будущие научные связи можно оценивать backtesting-ом на исторических графах. Есть работы, где именно influence statements + citation graph использовались для предсказания будущих научных открытий.

### Но для КЗ я бы не использовал только обычный `link prediction`

Твоя единица оценки:

```text
Article = множество утверждений
```

Поэтому нужно оценивать:

```text
PredictedStatements(A → future)
vs
ActualStatements(future article)
```

и считать хотя бы:

```text
Precision@K
Recall@K
F1@K
MRR
Hits@K
```

MRR и Hits@K являются стандартными метриками для задач прогнозирования фактов в временных knowledge graphs.

---

# 2. Очень важный момент — матчить нужно именно утверждения

Например:

### Предыдущая статья

```text
A1: rapamycin → inhibits → mTOR
A2: mTOR → regulates → autophagy
A3: autophagy → changes → lifespan
```

### Предсказанная будущая статья

```text
B1: rapamycin → inhibits → mTOR
B2: mTOR → increases → autophagy
B3: autophagy → increases → lifespan
```

Текст статей здесь вообще не нужен.

Сначала canonicalize:

```text
Statement
=
canonical subject
+
canonical predicate
+
canonical object
+
context
+
epistemic status
```

и затем находить соответствие `A_i ↔ B_j`.

То есть:

```text
Article1
   │
   └── {S1,S2,S3}

Future Article
   │
   └── {S4,S5,S6}

compare:
{S1,S2,S3} ↔ {S4,S5,S6}
```

---

# 3. Критерий №2 — насколько далеко удалось предсказать

Это была более оригинальная часть твоей идеи.

Недостаточно получить:

```text
A → B
```

если `B` находится почти рядом с `A`.

Ты хочешь:

> **как можно раньше предсказать знание, которое находится как можно дальше в графе.**

Поэтому для каждого успешного предсказания вычисляем расстояние:

```text
distance(
    previous_article,
    predicted_article
)
```

Но опять-таки **не между текстами или узлами Article**, а через их утверждения.

Например:

```text
Article A
  └── S1

S1 → S2 → S3 → S4 → S5

Article B
  └── S5
```

Тогда:

```text
distance(A,B) = 4
```

если путь:

```text
S1 → S2 → S3 → S4 → S5
```

является кратчайшим релевантным путём.

---

# 4. Но мы пришли к важной детали: одного расстояния между статьями недостаточно

Потому что статья содержит **много утверждений**.

Допустим:

```text
Article A = {A1,A2,A3}
Article B = {B1,B2,B3,B4}
```

и:

```text
A1 → B1       distance 2
A2 → B2       distance 7
A3 → B3       distance 15
```

Тогда нужно не брать просто один shortest path между Article-узлами.

Я предлагал считать расстояния **по всем совпавшим утверждениям** и затем агрегировать.

Например:

```text
ArticleDistance(A,B)
    = max(statement_distance)
```

или дополнительно:

```text
mean_distance
median_distance
max_distance
90th_percentile
```

Но для твоей основной идеи наиболее интересен:

> **максимально далёкое корректно предсказанное утверждение.**

---

# 5. Поэтому два критерия вместе можно представить так

Для каждого момента времени:

```text
Historical graph G(t)
        │
        ▼
   Previous article A
        │
        ▼
 Rule-based predictor
        │
        ▼
 Ranked predicted statements
        │
        ▼
 Future real articles
        │
        ├───────────────┐
        ▼               ▼
  Prediction quality   Graph distance
```

И получаем:

```text
Criterion 1:
"Попал ли будущий Statement в предсказания?"

Criterion 2:
"Насколько далеко этот Statement находился
от исходной статьи в графе?"
```

---

# 6. Я бы строил один главный показатель — Prediction Horizon

Для твоей идеи можно ввести:

```text
Prediction Horizon = graph distance
                      до впервые реально появившегося
                      предсказанного утверждения
```

Например:

```text
Статья 2015
    ↓
предсказание
    ↓
утверждение X

X реально появляется только в статье 2023
```

и расстояние:

```text
12 hops
```

Тогда:

> **Карта Знаний предсказала знание за 12 графовых переходов до того, как оно появилось в литературе.**

Это намного интереснее обычного `accuracy`.

---

# 7. И обязательно нужен временной split

Иначе будет утечка будущего.

Для каждого года:

```text
Train graph:
articles <= 2015

Predict:
articles 2016+

Evaluate:
только статьи, опубликованные после 2015
```

Затем:

```text
2015 → predict 2016–2018
2016 → predict 2017–2019
2017 → predict 2018–2020
...
```

Это стандартная логика temporal knowledge graph forecasting: модель использует исторические факты для прогнозирования будущих.

---

# 8. Библиографические связи тоже нужно учитывать

Это особенно важно для твоей КЗ.

У тебя граф:

```text
Statement graph
       +
Citation graph
       +
Document membership
```

То есть:

```text
Article A
  │
  ├── contains → S1
  ├── contains → S2
  │
  └── cites → Article C
                    │
                    └── contains → S10
```

При прогнозировании можно разрешить алгоритму использовать:

```text
Article → Article
```

по библиографии и:

```text
Statement → Statement
```

по знаниям.

Тогда ты можешь отдельно оценить:

```text
knowledge-only prediction
citation-only prediction
combined prediction
```

И это будет очень полезный эксперимент.

---

# 9. Обязательно нужен baseline

Иначе непонятно, хороша ли КЗ.

Я предлагал сравнивать минимум с:

```text
Baseline 1:
случайные статьи

Baseline 2:
most popular / most frequent statements

Baseline 3:
nearest neighbors

Baseline 4:
bibliographic citation prediction

Baseline 5:
graph shortest-path heuristic

Knowledge Map:
full rule-based algorithm
```

Тогда можно получить:

```text
Baseline:
Recall@10 = 2%

Knowledge Map:
Recall@10 = 15%
```

и уже говорить:

> КЗ действительно предсказывает будущее лучше простого baseline.

---

# 10. Самое важное — не дать критерию №2 стать читерством

Есть одна потенциальная проблема.

Если алгоритм просто выбирает огромные пути:

```text
A → X → X1 → X2 → ... → Z
```

он может искусственно увеличивать distance, но практически ничего полезного не предсказывать.

Поэтому **критерий №2 нельзя оптимизировать отдельно от критерия №1**.

Я бы использовал что-то вроде Pareto/frontier:

```text
X-axis = Prediction quality
Y-axis = Prediction distance
```

И строил точки:

```text
             ↑ distance
             │
             │        ●
             │   ●
             │
             │ ●
             └────────────────→ quality
```

Хорошая КЗ должна двигаться:

> **вправо и вверх.**

То есть одновременно:

```text
↑ accuracy
↑ prediction horizon
```

---

# 11. В итоге я бы формально определил два главных benchmark-а

### Benchmark A — Future Statement Prediction

Для каждой исторической статьи:

```text
Input:
all statements + graph available before t

Output:
ranked list of predicted statements/articles

Metric:
Precision@K
Recall@K
F1@K
MRR
Hits@K
```

### Benchmark B — Long-range Discovery

Для **правильно предсказанных утверждений**:

```text
d = shortest_path_distance(
        source_statement,
        future_statement
    )
```

и измеряем:

```text
mean(d)
median(d)
max(d)
P90(d)
```

Но основной показатель я бы сделал:

```text
Long-range Recall@K(d ≥ D)
```

Например:

> Какой процент будущих истинных утверждений, находящихся минимум в 10 hops от исходной статьи, система смогла предсказать в top-100?

Вот это уже непосредственно измеряет твою идею:

> **«Насколько рано мы можем предсказать насколько далёкое знание?»**

---

## И ещё лучше — связать оба критерия

Можно построить таблицу:

|   Distance | Recall@100 |
| ---------: | ---------: |
|   1–2 hops |        32% |
|   3–5 hops |        21% |
|  6–10 hops |        14% |
| 11–20 hops |         7% |
|   >20 hops |         2% |

Тогда график сразу показывает реальную способность КЗ к **дальнему научному предсказанию**.

И я бы именно эту пару метрик считал наиболее интересным доказательством работоспособности твоей идеи: **не просто «Карта Знаний находит известные связи», а «из состояния знаний на момент T она может правилами предсказать утверждение, которое появится позже и находится далеко от исходного знания в графе».** Научная литература по temporal KG forecasting уже использует временное backtesting и ranking metrics; твой вклад здесь будет в том, что **объектом прогнозирования и оценки станет не абстрактный edge/entity, а набор канонических утверждений конкретной будущей статьи, а отдельной метрикой станет дальность этого предсказания в графе**.

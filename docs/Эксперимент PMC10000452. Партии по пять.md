# Накопительный пилот PMC10000452

Эксперимент проверяет прямую карту знаний и символьное прогнозирование на библиографических источниках PMC10000452. Первый контрольный корпус содержит пять доступных полных английских текстов. Следующий корпус добавляется только после совместного разбора результатов.

## Границы эксперимента

- Используется production-сценарий `TextToMap`, идентификатор `text_reified`, схема 5. Сначала настроенный профиль `article_extraction` извлекает знания, затем тот же профиль проверяет зависимости. Структурные строки и прежний построитель не участвуют.
- Реестр восстанавливается из оригинального JATS целевой статьи: обязательны все ссылки 1–54. Метаданные разрешаются через Crossref, Europe PMC и OpenAlex; OA-текст принимается только после фактического скачивания полного JATS или PDF. Аннотация не заменяет текст. Недоступные URL, неподтверждённый доступ и неоднозначные даты перечисляются отдельно.
- Порядок фиксируется до прогнозирования: Cretan Aging Cohort и прежние работы её авторов; исследования когнитивного снижения; остальные ссылки. Внутри групп используется номер ссылки. Источники позднее 27.02.2023 не включаются.
- Обучение получает исключительно перечисленные версии пяти карт. Предиктор не обращается к Neo4j, S3, LLM или карте цели. Библиография используется для выбора корпуса, а не как dependency-связи знаний.
- Канонизация выполняется над готовыми картами. Сохраняются участники, предикаты, роли, тип знания, отрицание, числа, кванторы, модальность, условия и время. Синонимы сопоставляются по явно объявленным aliases обучающих источников; неоднозначные сокращения не объединяются.
- Неиспользуемые, но корректно привязанные к источнику названия скрытого словаря отмечаются в `unused_concept_ids`. Они не являются блоками утверждений или узлами DAG и исключаются из обучения синонимам. Ошибка происхождения такой записи по-прежнему отклоняет весь ответ.
- Извлечение и построение зависимостей имеют отдельные версии промптов. Этап зависимостей версии 14 проверяет заранее определённые непересекающиеся группы по 40 целевых блоков. Каждый запрос получает полный текст, всю извлечённую карту, уже проверенные связи и текущий список dependency_target_keys. Возвращается полный массив входов текущих целей: source, target, usage, reason, unit_ids. Источник может принадлежать любой группе; порядок групп не задаёт направление знаний. Короткие рабочие id прикреплены к полным текстам. Strict-схема ограничивает target текущей группой, source — всей картой; все пять полей обязательны. После группы проверяется DAG объединения, перед единственным сохранением — весь граф и охват всех целей. Блоки, включая независимые, сохраняются; ранги вычисляются сервером. Циклы, дубли, неизвестные концы, неверное происхождение и незавершённые ответы отклоняются без публикации частичной карты. Результат содержит точные метаданные всех групп и совокупный usage. Совместимые группы переиспользуются только при точном совпадении ранее принятых связей и остальных зависимостей запроса. Межпроцессная блокировка продлевается перед группами. Модель gpt-6-luna и reasoning_effort=max сохранены по решению пользователя; извлечение версии 2 не менялось. Контраст независимых фактов не создаёт взаимных зависимостей; цель исследования не обосновывает численные результаты. Usage ограничен семью способами использования знания. Исправление зависимостей сохраняет совместимое извлечение и перевод неизменённых подписей. Старые ответы и карты неизменяемы; несовместимые версии не смешиваются.
- Статистические шаблоны содержат одно заключение и от одной до трёх предпосылок. Поддержка требуется минимум в двух различных источниках. Заключение не может вводить свободного участника, отсутствующего в предпосылках. Ассоциация не получает автоматически свойства транзитивности.
- Сравниваются объединение известных знаний, символьный прогноз без dependency-связей и прогноз с ними. Прогнозы двух предикторов содержат до 20 новых гипотез с шаблоном, предпосылками и источниками. Пустой прогноз допустим. Для графового режима сохраняется направление внутренних связей предпосылок; обязательные входы заключения не отбрасываются ради лимита трёх.
- Прогнозы записываются до получения карты цели. Оценщик отличает точное совпадение, несовместимый контекст, явное отрицание и отсутствие подтверждения. Отсутствие утверждения в цели не считается опровержением. Повторение знаний отдельно от нового прогноза.

PMC10000452 использовалась при разработке промпта и является отладочным случаем. Совпадения с её автоматической формализацией и технически корректный DAG не доказывают научную точность или способность предсказывать будущие открытия. После фиксации правил нужна ранее не использованная цель.

В scoped-схеме для каждой текущей цели задана отдельная `anyOf`-ветвь: `target` фиксирован
через `const`, `source` ограничен конечной regex-альтернативой известных id. Из источников
исключены сама цель и её потомки по уже проверенным связям. Это запрещает самоссылки
и обратные входы по существующим путям до генерации. Общий enum usage не размножается
сверх лимита 1 000 enum-значений; `not`, `if`, `allOf` и lookaround не используются.
Циклы между новыми связями дополнительно проверяются в полном объединении. Изменение
схемы инвалидирует прежние успешные групповые ответы: они архивируются, но не смешиваются
с новой схемой и не исправляются вручную. Извлечение и неизменённые переводы переиспользуются.
Поддержка `anyOf`, строкового `pattern` и ограничения схем описаны в
[официальной документации OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs).

## Запуск

Windows CLI запускается в PowerShell от имени администратора из `D:\Knowledge_Map\api`. Проверка прав встроена в команду. Python запускается только через Poetry.

```powershell
poetry run python tools/run_reference_pilot.py prepare
poetry run python tools/run_reference_pilot.py intake --size 5
poetry run python tools/run_reference_pilot.py run --size 5
```

`prepare` собирает реестр и проверяет скачивание OA-оригиналов без LLM. `intake` сохраняет выбранные пять текстов и новую полную ревизию цели без LLM. `run` выполняет формализацию, канонизацию, обучение, фиксацию прогнозов, оценку и русский отчёт. Подписи карт переводятся отдельно; ошибка перевода не меняет английскую семантику.

Используются настроенные адреса Neo4j, S3 и AI-сервиса; XML gRPC — 50054, PDF gRPC — 50053. CLI не запускает сервисы и не выбирает другие порты, модели или сокращённый текст. После изменения сервиса пользователь перезапускает его согласно AGENTS.md.

Параметры: `--owner-article` определяет владельца по исходной GOLD-статье; `--output` задаёт каталог артефактов; `--refresh-registry` явно создаёт новую ревизию реестра. При изменении доступности нельзя одновременно менять правила и состав уже завершённого корпуса: сценарий проверяет прежний состав. `--no-translation` явно отключает только отдельный перевод подписей, если он не нужен для конкретного технического повтора.

## Артефакты и возобновление

По умолчанию артефакты находятся в `eval/reference_pilots/pmc10000452`, исключённом из Git. Каталог переопределяется `REFERENCE_PILOT_DIR`. В Docker API используется `/data/reference_pilots/pmc10000452`, подключённый отдельным томом. Для запуска CLI внутри контейнера адреса внешних конвертеров должны быть настроены через `XML_TO_MD_SERVICE_HOST/PORT` и `PDF_TO_MD_SERVICE_HOST/PORT`; сами сервисы должны быть доступны в соответствующей сети.

- `registry/revisions/`: неизменяемые реестры и хеш оригинального XML цели; `registry.json`: выбранная ревизия.
- `downloads/`: полные скачанные оригиналы по SHA-256.
- `sources/<id>/revisions/<sha>/`: полный Markdown, оригинал и метаданные GOLD-совместимой автоматической копии с `needs_expert_review=true`. Документ и S3-ключ отдельные; старые GOLD-эталоны не перезаписываются.
- `requests/`, `responses/`, `attempts/`: точные промпты и запросы, ответы, параметры модели, хеши и расходы каждого вызова. Полные научные тексты остаются в артефактах, а не в обычных логах. Каталог требует обычного контроля доступа и резервного копирования.
- `stage_cache/`: только завершённые и валидированные ответы. Ключ зависит от источника, точного запроса, промпта, схемы ответа, валидатора и параметров модели. Неполный или некорректный ответ сохраняется для диагностики, но не переиспользуется.
- `maps/`: неизменяемые карты со всеми версиями. Пересборка зависимостей может переиспользовать неизменённое извлечение. Изменение общего промпта извлечения инвалидирует весь накопленный корпус перед сравнимым повтором. Смешивание несовместимых карт запрещено.
- `translations/<run_id>/`: русские подписи конкретного английского результата; идентификаторы и семантика не меняются. Перевод также архивирует точные запросы и ответы и использует проверяемый кэш этапа. Если изменены только зависимости, а английские подписи, идентификаторы, текст источника, промпт, схема, валидатор и настройки модели прежние, перевод переиспользуется и привязывается к новому результату без LLM-вызова.
- `target/initial_existing_gold_map.json`: исходная сохранённая GOLD-карта; `target/anchor.json`: первая контрольная карта исправленного полного текста. Последующие результаты не изменяют эти контрольные артефакты.
- `diagnostic_calls/`: точные запросы, ответы и usage синтетических проверок. Они не входят в обучение; расходы учитываются отдельно от научных этапов.
- `runs/<run_id>/`: зафиксированные прогнозы, JSON-отчёт и `report.ru.md`. Хеши реестра, анализа и версий карт позволяют отличить изменение алгоритма от изменения данных.
- `cost_ledger.json`: накопленные вызовы, включая отклонённые ответы; в отчёте расход и переиспользование разделены по этапам. Неизвестный usage не равен нулю.

AI-сервис сохраняет доступные счётчики незавершённого ответа, включая reasoning tokens, и передаёт безопасную причину `response.incomplete`. Неполный ответ не становится кэшем или картой. Ранний исторический перевод до введения кэша переводов учитывается в расходе и связан с конкретной картой, но его точный запрос не был архивирован; это ограничение отмечается отдельно при аудите.

Строгие JSON-запросы AI-сервис выполняет как одну фоновую генерацию Responses (`stream=false`, `background=true`, `store=true`). Сразу сохраняется id и хеш точного upstream-запроса; GET читает только этот id, пока статус `queued` или `in_progress`. Содержимое принимается только при `completed`. Штатный клиентский SSE-контракт сохраняется: служебные метаданные, полное завершённое содержимое, подтверждённый `stop`, usage и завершающий кадр. Модель, параметры генерации, схема, промпты и полный текст не меняются. После ошибки автоматического повторного POST генерации нет; повтор временно неудачного GET читает тот же ответ и не запускает модель. Отключение клиента, таймаут или отказ чтения отменяют собственное незавершённое фоновое задание. Отказы `incomplete`, `failed`, отмена и неизвестный статус не публикуют содержимое, включая частичный ответ; архивируется безопасная диагностика с id и доступными счётчиками. Поля `upstream_transport`, `upstream_status` и `upstream_request_sha256` сохраняются в метаданных вызова. Совместимые полностью проверенные карты прежних вызовов сохраняют свои точные архивные запросы и ответы. Контрольные точки создаются только по завершённым проверенным ответам; неполный upstream-ответ не является результатом для обучения или кэша.

При обрыве транспорта сохраняются также безопасные метаданные частичного ответа: хеш, длительность, признаки завершения и доступные счётчики. Отсутствие usage после закрытия потока не трактуется как нулевой расход или подтверждённый лимит токенов. Старые частичные ответы без таких метаданных остаются в архиве и отмечаются как ограничение проверки хеша; они никогда не используются для карты или обучения.

У первого исторического извлечения поле транспортного response_sha256 вычислялось над JSON-кодированной строкой. Хеш исходных UTF-8-байтов сохранён в имени файла ответа и квитанции повторной проверки. Верификатор явно воспроизводит оба алгоритма только для этой исторической попытки и отмечает различие; записи и ответ не переписываются. Текущий транспорт хеширует исходные байты.

При ошибке повторяется та же команда с тем же `--size`. Прежнее успешно завершённое состояние сохраняется; проверенные совместимые этапы переиспользуются. Параллельные CLI блокируются `writer.lock`; карты дополнительно защищены штатными блокировками Neo4j. При аварийном завершении сначала проверяют PID в lock и отсутствие работающего процесса, затем явно восстанавливают блокировку. Автоматического снятия чужой блокировки нет.

По умолчанию карты строятся последовательно: крупные полные тексты не должны вместе превышать квоту настроенного провайдера на входные токены в минуту. Параметр `--map-concurrency` явно задаёт лимит от 1 до 5, если квота допускает параллельные запросы. При отказе новые задачи не запускаются, уже начатая соседняя карта завершается и сохраняет проверенные этапы. Порядок корпуса фиксирован независимо от порядка завершения LLM-запросов; лимит записывается в артефакты прогона. Автоматического переключения модели или сокращения текста нет.

Если исправлен только валидатор, существует явная команда повторной проверки сохранённого исходного ответа:

```powershell
poetry run python tools/run_reference_pilot.py revalidate --attempt-id <UUID>
poetry run python tools/run_reference_pilot.py run --size 5
```

Она не исправляет JSON, не вызывает LLM и не публикует карту. Требуются неизменные источник, точный запрос, промпт, схема ответа и параметры модели. Ответ полностью проверяется новым валидатором; только успешная проверка создаёт новую совместимую запись кэша. Исходный отказ и его расход сохраняются, переход версий записывается отдельной квитанцией. При изменении промпта или модели такая повторная проверка запрещена.

После первого отчёта работа останавливается на пяти источниках. Исправление правил сначала проверяется повтором `run --size 5`. После согласования добавляется следующая партия через `run --size 10`. Сценарий запрещает перескочить контрольную точку или незаметно уменьшить корпус.

## Проверки

Тесты `test_reference_prediction.py` создают контрольные задачи для нескольких предпосылок, синонимов, неоднозначных сокращений, отрицаний, кванторов, модальности, чисел и несовместимого контекста. `test_reference_pilot.py` проверяет изоляцию цели, неизменяемость артефактов, остановку на пяти, версии, кэш и сохранность состояния при ошибках. XML-регрессия проверяет сохранение всех ссылок при библиографии длиннее 50. Штатные проверки карты контролируют DAG, роли, происхождение и усечённые ответы.

```powershell
poetry run pytest tests/unit/application/test_reference_prediction.py tests/unit/application/test_reference_pilot.py
```

Проверки клиента выполняются из `client` через `bun run typecheck`, `bun run test:run` и `bun run build`. Git-коммиты не создаются.

## English summary

This pilot uses only the production full-text knowledge-map pipeline and explicitly frozen source map revisions. Five-source checkpoints stop for joint review. The target is accessible only after predictions have been sealed. Exact semantic matching is conservative, statistical hypotheses are not logical proofs, and automatic validation is not expert scientific review. Source revisions, map versions, stage caches, translations, predictions, and token accounting are preserved separately.

Отклонённые кандидаты не включаются в массив принятых входов. Каждая запись создаёт действующее ребро; обоснование, отрицающее саму зависимость, не отменяет эту запись. Отрицательный научный факт может быть полноценной предпосылкой. Циклический ответ отклоняется целиком; исходный ответ и предыдущая успешная карта сохраняются.

В исторической версии 12 каждый целевой блок имеет строго именованный объект `inputs`: это входящие предпосылки, а не исходящие применения знания. Например, индивидуальные измерения двух исследований подаются на их объединённую оценку только в её `inputs`. Обратные записи требуют отдельного обоснования и не создаются зеркально. Все целевые ключи обязательны; блок без входов имеет `{"inputs":[]}`.

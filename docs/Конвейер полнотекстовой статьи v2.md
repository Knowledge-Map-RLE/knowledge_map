# Конвейер полнотекстовой статьи v2

Этот документ описывает канонический путь обработки статьи:

```text
Original Markdown revision -> Linguistic profile -> Structural blocks v2 -> Knowledge Map v2
```

## Исходник и диапазоны

`Document.uid` является идентификатором статьи. Каждая неизменяемая `SourceRevision` содержит исходный Markdown без нормализации, SHA-256 и кодировку смещений `unicode_codepoints`. Диапазон всегда является полуинтервалом `[start, end)` в Unicode-кодовых точках именно этой ревизии. Markdown и References остаются в исходнике и лингвистической структуре; библиография, авторы и административные сведения не становятся биологическими утверждениями.

## Лингвистический профиль

Лингвистический профиль хранит предложения, все токены исходника, зависимости, фразы, секции и их диапазоны. Валидатор проверяет точное совпадение текстов токенов, покрытие исходника, отсутствие битых ссылок и соответствие токенов диапазону.

Извлечение выполняется по целой статье без разбиения на фрагменты через cloud.ru Foundation Models (`deepseek-ai/DeepSeek-V4-Flash`). Два прохода получают весь исходник: сначала модель объявляет все локальные `C…` и `A…`, затем реализует каждое объявленное утверждение. Фиксированного ограничения на число понятий и утверждений нет. Второй ответ обязан содержать ключ каждого `A…`: полное типизированное утверждение либо `unresolved_reason`. Это исключает молчаливую потерю фрагмента. Неопределённости сохраняются в `issues`; карта содержит только прошедшие валидацию утверждения. Модель не получает эталон утверждений.

## Structural blocks v2

Совместимый контейнер имеет вид:

```json
{"instanceId":"uuid","schemaVersion":2,"blockType":"entity|statement","data":{},"order":0}
```

`entity` — самостоятельный Concept. `statement` — Assertion со статусом `hypothesized`, предикатом `{id,label,arity}`, `negated`, `modality`, `context` и provenance. Аргумент имеет один из видов:

```json
{"kind":"concept","id":"uuid"}
{"kind":"assertion","id":"uuid"}
{"kind":"literal","value":"4.5","unit":"years"}
```

Одноместный предикат имеет `arity: 1` и `object: null`. `is_a` не является служебным шумом. Идентичность определяется типизированными идентификаторами, а не текстом отображения.

## Карта, версии и provenance

Карта отображает каждый структурный блок и хранит предметные `semantic_edges` отдельно от визуальных `dependency_edges`. Проверка DAG применяется только к визуальным зависимостям. Логический вывод не является частью извлечения.

Neo4j сохраняет SourceRevision, ArticlePipelineRun, SLGNode, SourceSpan, ArticleBlock, KnowledgeConcept и KnowledgeStatement. Трассировка:

```text
Map entity -> Concept/Statement -> ArticleBlock -> SourceSpan -> SourceRevision -> Document
```

Сохранение одной версии идемпотентно. Новая версия не применяется автоматически; `save=true` создаёт версию, а пользователь явно применяет её после проверки актуальности исходной контрольной суммы. При применении прежние редакторские блоки и утверждения сохраняются в `ArticleEditorSnapshot`. Старые статьи остаются legacy-данными: точная provenance доступна после явной переобработки исходника.

## Совместимость и прежняя документация

Прежние описания, где триплет определяется как короткие текстовые Subject/Predicate/Object, UUID используется как текстовый placeholder или `is_a` отбрасывается как шум, относятся к legacy-потоку. Они не задают идентичность данных v2. Утверждения `FACT` и `META` также не определяют достоверность нового извлечения: новые Assertions всегда получают `hypothesized`.

## API

`POST /article_editor/articles/{doc_id}/llm-extract` сохраняет run/version и передаёт стадии через SSE. Доступны список версий, состояние версии, результаты отдельных стадий, provenance выбранной сущности и явное применение версии. Интерфейс показывает английский текст, исходный выделенный диапазон, Structural block и замечания; отдельный редактор промежуточного слоя не предоставляется.

## Параметры cloud.ru и воспроизводимый запуск

Конвейер использует AI-шлюз на порту 50059, NLP на 50055 и текущую Neo4j.
`LLM_EXTRACT_MODEL=deepseek-ai/DeepSeek-V4-Flash`, `LLM_CONTEXT_LENGTH=1048576`,
`LLM_MAX_TOKENS=80000`, `LLM_TIMEOUT=1800`. Контекст подтверждён каталогом cloud.ru;
выходной бюджет 80000 принят сервисом в проверочном запросе (это настроенный бюджет,
а не утверждение о максимальном выходе модели). `thinking.type=disabled` отключает
дополнительный reasoning. Ответ с `finish_reason` кроме `stop` не принимается.

Схема ссылок использует только объявленные идентификаторы; ссылки на неизвестные
и неразрешённые утверждения отклоняются. Общие определения аргументов и evidence
вынесены в `$defs`, чтобы схема второго прохода не росла квадратично.

Для запуска из каталога `api`:

```powershell
poetry run python -u -m tools.run_article_pipeline --output D:/Knowledge_Map/data/pipeline_runs/acomys-cloudru
```

`--resume` разрешён только для того же исходника и режима извлечения. Старые
фрагментированные checkpoints нельзя смешивать с новым полнотекстовым прогоном.
Журнал содержит модель, бюджет и фактический расход токенов, время каждого запроса.
Исходный ключ cloud.ru хранится только в окружении AI-сервиса / `app-secrets`.

# Переводы GOLD-статей

Английские `article.md`, `gold.json`, `meta.json` и контрольные суммы остаются неизменными. Полный русский Markdown хранится рядом с источником как `article.ru.md`. Runtime sidecar `translation.ru.json` содержит тот же Markdown и локализацию структурных строк и должен соответствовать схеме `translation.schema.json`.

`source_file_sha256` — SHA-256 точных байтов `article.md`; `source_article_sha256` — исходный идентификатор статьи из `meta.json`. Сервер сверяет обе суммы до выдачи перевода. Это не позволяет случайно показать перевод от другой редакции статьи.

`rows_by_tag` использует стабильные структурные теги `B<n>`, а не генерируемые Neo4j UUID. Если в кейсе есть экспертный `gold.dsl`, теги и типы берутся из него; иначе используются структурные строки legacy `gold.json`. Для каждой строки, показываемой в GOLD-редакторе или карте, нужен `display_text`; `type_name` задаёт локализованную подпись типа строки. При отсутствии перевода сервер отвечает ошибкой и не подменяет его исходным английским текстом.

Совпадения одного тега недостаточно: сервер также сверяет тип и исходные DSL-поля строки. Это исключает подстановку перевода из другой структурной редакции с той же нумерацией.

## Сохранённые структурные версии без B-тегов

Старые версии в Neo4j могут содержать другой набор структурных блоков и не иметь `data.tag`. Их перевод хранится отдельно в `translation.ru.saved-blocks.json` по схеме `translation.saved-blocks.schema.json`. `rows_by_tag` при этом продолжает описывать экспертный DSL.

`blocks_by_fingerprint` связывает ручной перевод с SHA-256 канонического JSON исходного блока: `{"blockType": block.blockType, "data": block.data}`. JSON сериализуется с `ensure_ascii=False`, `sort_keys=True`, `separators=(",", ":")` и кодируется в UTF-8. Сверяются весь payload блока, контрольная сумма статьи и контрольная сумма legacy DSL. Изменившийся блок требует перевода своей редакции; локальные B-теги, добавленные при построении карты, для сопоставления не используются.

Сервер сопоставляет подпись узла карты с уже локализованным блоком по `structural_id` (либо `id` для узла, идентификатор которого равен идентификатору блока). Рёбра, ранги, исходные поля и сохранённые версии карты не изменяются при переключении языка.

Для `gold-pmc10000452-v3` сохранены переводы всех 792 блоков. Термины переведены вручную; утверждения сопоставлены по уникальным исходным тройкам, остальные строки — по точным проверенным исходным фрагментам. Заголовки и метаданные переведены явно. Модели и API перевода не используются.

Для `gold-pmc10000584-v3` сохранены переводы всех 912 блоков: 396 вручную переведённых терминов, 222 утверждения с уникальным точным совпадением исходной тройки, 292 строки с проверенным исходным фрагментом и 2 явно переведённых заголовочных блока. Сборщик `.gold_manual_work/build_saved_gold_case_localization.py` проверяет контрольные суммы, редакцию DSL, исходные диапазоны, полноту ручных переводов и отсутствие дубликатов перед записью sidecar. Он не обращается к моделям и не изменяет БД.

Текст и структурная редакция загружаются независимо. Запрос `/localization?scope=article` проверяет идентичность и контрольные суммы статьи, затем возвращает русский Markdown без чтения структурных артефактов. Запрос `/localization?scope=structure` дополнительно проверяет все сохранённые блоки; этот режим используется по умолчанию. Ошибка перевода структурной редакции не блокирует отдельный перевод текста. Непереведённые строки редактора не заменяются английскими.

Каталог корпуса задаётся настройкой API `ARTICLE_PIPELINE_GOLD_DIR`. В контейнере он включён в образ по пути `/data/article_pipeline_gold`; Compose монтирует локальный корпус в этот путь в режиме чтения.

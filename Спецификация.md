# Спецификация Карты Знаний

Цель Карты Знаний: ускорить науку, через структурирование знаний, для создания терапии старения и для продления жизни человеку.

- Микросервисная архитектура
- Есть возможность преобразовывать PDF в Markdown
- Текст Markdown должен преобразовываться в триплеты Языка Знаний
- В интерфейсе триплеты должны превращаться в обычный текст или карту знаний
- Сервер должен считать количество заходов на сайт и количество уникальных пользователей
- Веб-приложение должно быть защищено от злоумышленников

## Каноничные данные из которых должна состоять научная статья. Новый формат научных статей

- Эти данные должны быть предоставлены при создании новой статьи сразу в нужном для Карты Знаний формате.
- Должна быть возможность через классические или AI алгоритмы извлекать эти данные из cуществующих научных статей.
- Вне зависимости от способа это то что должно быть получено в итоге из статьи и должно проверяться валидатором при написании статьи.
- В интерфейсе Карты Знаний, должны быть показаны примеры каждого из пунктов при наведении на иконку вопроса.
- Это может помогать в планировании исследования.

Структурные строки:
- Метаданные (только 1 стуктурная строка на статью)
  - Обозначение: `metadata`
  - Поля
    - DOI
    - Название статьи
    - Авторы статьи (список) с ORCID авторов если есть
    - Организации (список)
    - Corresponding author (список)
    - Дата публикации
    - Журнал
    - Том
    - Выпуск
    - Страницы
    - Publisher
    - Лицензия
    - Финансирование (список)
    - Конфликт интересов (список)
    - Регистрация исследования
- Универсальное поле для прямого создания утверждения из триплета
  - Обозначение: `statement`
  - Поля
    1. Субъект
    2. Предикат
    3. Объект
- Цель исследования (Формулировка научной задачи, проверка эффекта воздействия А на B)
  - Обознвачение: `goal`
  - Поля
    1. Субъект
    2. Предикат
    3. Объект
- Поле со свободным форматом — сплошным текстом, для чего нет полей
  - Обознвачение: `text`
  - Поля
    - Текст
- Гипотеза
  - Обозначение: `hypothesis`
  - Поля
      - Гипотеза
        1. Субъект
        2. Предикат
        3. Объект
      - Опровержение гипотезы ❗
        1. Субъект опровержения
        2. Предикат опровержения
        3. Объект опровержения
  - Комментарии
    - Что пытаемся опровергнуть?
    - Пояснение почему нужно именно опровержение — ❗
- Предпосылки — граф с онтологией, из которой исходит исследователь (Утверждения на которые он опирался. Контекст). На какие знания в виде утверждений опираемся? Знания-зависимаости.
  - Обозначение: `prerequisite`
  - Поля:
    - Список утверждений (список)
- Что ожидаем получить после исследования?
  - Обозначение: `expectations`
    - Поля:
      - Список утверждений (список)

- Дизайн исследования ❗
  - Обозначение: `research_design`
  - Поля
    - Тип исследования
      - Case Report (Отчет по одному случаю) — описание одного пациента
      - Case Series (Отчёт по нескольким случаям) — описание нескольких похожих случаев
      - Статья A реплицирует статью B — Репликация — независимое повторение (воспроизведение) существующего исследования
        - Противоречия или поддержание с существующими статьями
      - Original Research (Оригинальное исследование) — должны давать новые данные
      - Review (Обзор) — анализирует несколько существующих исследований в одной статье (хуже мета-анализа). Новых экспериментов нет
      - Systematic Review (Систематический обзор) — делается по протоколу, где будут искать статьи, какие статьи включат и какие исключат
      - Статья мета-анализ — проводит точный расчёт исследований по размеру эффекта среди огромного количества статей (считается самым сильным доказательством)
      - Clinical Trial (Клиническое исследование) — проводится на людях, имеет 4 фазы
        - Фаза I — безопасность, переносимость, дозировка; обычно небольшое число здоровых добровольцев.
        - Фаза II — эффективность и подбор дозы у пациентов.
        - Фаза III — подтверждение эффективности и безопасности на большой группе пациентов, сравнение со стандартом/плацебо.
        - Фаза IV — наблюдение после регистрации: долгосрочная эффективность и редкие побочные эффекты.
    - Рандомизация (рандомизированное контролируемое исследование, RCT) (чекбокс)
    - Ослепление (чекбокс)
- Материал
  - Обозначение: `material`
  - Поля
- Метод. Логика исследователя (Методология?)

Уверенность в доказательствах (Certainty of Evidence) — именно этот термин используется системой GRADE). Лучше хранить не число и не категорию, а список, почему именно нужно доверять утверждению (поддерживается → 18 экспериментов, опровергается → 2 экспериментами, реплицировано → 11 раз, RCT → 7, Meta-analysis → 3, Средний effect size → 0.74, Средний CI → ..., Общая выборка → 48 000, Независимых лабораторий → 14, Биологический механизм → известен). Или вектор доказательств (Статистическая поддержка = 0.96, Воспроизводимость = 0.91, Причинность = 0.84, Биологическая правдоподобность = 0.88, Согласованность исследований = 0.93 Качество дизайна = 0.79) Зависит от:
    - Размер выборки
    - p-value
    - likelihood вместо p-values по идеям Элиезера Юдковского — оценивать научные гипотезы лучше не через p-value, а через отношение правдоподобия (likelihood ratio) и байесовское обновление вероятностей
    - Размер эффекта
    - Confidence Interval
    - Мощность исследования
    - Репликации
    - Тип исследования
    - Рандомизация
    - Ослепление
    - Контрольная группа
    - Риск систематической ошибки
    - Метаанализ
    - Биологический механизм
    - Количество независимых лабораторий
  - A активирует B
  - A ингибирует B
  - A нокаутирует B
  - A коррелирует с B — статистическая связь между переменными
  - A причина B — казуация — причинно-следственные связи

## Язык Знаний

Определение на языке спецификаций (БНФ Формы Бэкуса — Наура):
```bash
Statement ::= Identifier ":" Subject "→" Predicate "→" Object
Subject ::= Concept | Statement
Object ::= Concept | Statement | Literal
```

- Утверждение образует триплет с UUID идентификатором
- Язык Знаний является вычислимым
- Если объект или субъект триплета содержит идентификатор утверждения то должна быть функция раскрывающая все зависимые утверждения, то есть вместо идентификаторов подставляется триплет на который он указывает. Триплеты считаются раскрытыми если ни в одном не осталось идентификатора который может раскрыться
- Контекст — совокупность всех раскрытых триплетов текущего триплета
- Одно утверждение должно описывать ровно одно отношение между двумя объектами или объектом и одним значением. Subject и Object не должны содержать другого самостоятельного утверждения. Predicate должен выражать ровно одну семантическую связь.

- Subject
  - один самостоятельный объект/понятие;
  - выражается одной именной группой (noun phrase);
  - не содержит отдельного утверждения;
  - не содержит и / или, относительного придаточного, причинного/условного предложения.
- Predicate
  - одна семантическая связь;
  - в Knowledge Language хранится как один канонический предикат, например inhibits, causes, measured_in, located_in;
  - исходно в тексте он может состоять из нескольких слов, но после нормализации превращается в один идентификатор.
- Object
  - один самостоятельный объект/понятие или одно literal-значение;
  - также одна именная группа либо литерал;
  - не содержит второго утверждения.

- WYSIWYG редактор
- Статистика использования AI функций (токены, потрачено денег и так далее)

## Паттерны успешные и не успешные

- Успешным паттерном являются тот набор (граф) утверждений который приводит к положительному результату исследования или иначе, гипотеза подтвердилась (не опровергнута).
- Не успешным паттерном является тот набор (граф) утверждений который приводит к отрицательному (неправильному) результату исследования или иначе, гипотеза не подтвердилась или если исследование содержит ошибки в методах или дизайне исследования.
